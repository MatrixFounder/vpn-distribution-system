## 3. Замечания

### BLOCKING

**B-1.** Коэффициент трафика не датирован: `billing_groups.multiplier_milli` и
`nodes.multiplier_milli` хранят только текущее значение, тогда как §5.9 требует выбор по интервалу
`[period_start, period_end)` при буфере до 24 часов; правило закрытия периода агрегации при смене
группы (§4.9) не представлено. Исправление: история назначений с интервалами действия и
ограничением непересечения; разрешение по `period_start`.

**B-2.** Матрица влияния §4.6 не реализована в потоке состава: `Pending` и `Provisioning`
получают credentials вопреки §11.3 и AC-13; фильтрация «только отзывы» для `Disabled` и
`Suspended` несовместима с курсором `updated_seq > users_seq` (потеря строк); правило
«строка существует только при пересечении групп доступа» и привязка расшифровки к identity не
записаны. Исправление: вентиль по статусу в §5.2, признак `resync_required`, два правила
целостности в §4.4.

**B-3.** Обезличивание при удалении аккаунта (§16.4, R-13, AC-24) противоречит append-only
для `traffic_lines` и `audit_log`, объявленным тем же документом; суррогатного идентификатора нет.
Исправление: модель А — таблицы потребления и аудита не хранят персональных данных, `user_id`
остаётся суррогатом после стирания PII в `users`; правило «`old_value`, `new_value`, `ip` без PII».

### MAJOR

M-1 роли базы не позволяют обслуживать партиции и ретенцию (`app_rw` без DDL/DELETE; владелец не
назван); M-2 способ выделения `updated_seq` не задан — `nextval` теряет строки при обратном порядке
коммитов; M-3 состав `audit_log` без `impersonated_user_id`, `user_agent`, словарь `result` и
регистрация чтения журнала не по §4.16; M-4 нет журнала изменений баланса — сверка Н-18 и
корректировки не обеспечены; M-5 модель гранта не ограничивает суммарный перерасход по N нодам и
не хранит расход; M-6 гранулярность `traffic_lines` (60 с × 90 дней) расходится с Н-21/Н-22 —
нужна материализованная `traffic_hourly`; M-7 R-25 и R-29 не покрыты компонентами; M-8
`jobs.idempotency_key UNIQUE` без срока запрещает повторную постановку `aggregate:{day}`; M-9
механизм выборки задач и раскладка бюджета Н-13 не заданы; M-10 граница mTLS без правил
(`enroll` на том же пути, заголовок отпечатка, ключ частоты для `/enroll`); M-11 метка отката
хранится внутри восстанавливаемой базы; M-12 при отказе Redis лимит частоты на `/s/{token}`
отключается (fail-open); M-13 адреса входа и регистрации (§16.1, 90 дней) без носителя.

### MINOR

матрицы UC → F/C, UC-10 без компонента; m-6 `inbounds` без `trusted_x_forwarded_for` и полного

m-9 параметры argon2id не зафиксированы; m-10 SSRF при доставке webhook; m-11 Н-25 для журнала
приложения; m-12 модель конкурентности uvicorn и освобождение соединений при long-poll; m-13
домен писем и записи SPF/DKIM/DMARC в §10.4; m-14 сроки хранения для десяти таблиц; m-15 три info
