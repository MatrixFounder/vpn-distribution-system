# Задача 001.54: Node Agent: enrollment, хранение identity, mTLS-клиент, повторное подтверждение

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-01 Ввод ноды в эксплуатацию
- UC-10 Восстановление Control Plane из резервной копии

Требования RTM: R-02.

<!-- contract:goal -->

## Цель задачи

Реализовать обмен bootstrap-токена на сертификат, хранение identity в `/var/lib/node-agent` (0600),
HTTP-клиент с клиентским сертификатом, джиттер и экспоненциальную задержку, повторное подтверждение
при 401 по сохранённому секрету (§5.3 архитектуры).

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `node-agent/internal/enroll/enroll_test.go` — интеграционный тест против тестового сервера с mTLS

### Изменения в существующих файлах

#### Файл: `node-agent/internal/enroll/enroll.go`

- `func Enroll(ctx, cfg, token string) (Identity, error)`: CSR (ECDSA P-256), `POST /agent/v1/enroll`, запись `cert.pem`, `key.pem`, `ca.pem`, `token`

#### Файл: `node-agent/internal/cpclient/client.go`

- `tls.Config` с клиентским сертификатом и CA; заголовок `X-Agent-Version`; backoff 1 с → 60 с с джиттером; 401 → повторное подтверждение; 426 → остановка с ошибкой в журнале

### Интеграция компонентов

Токен identity и сертификат используются всеми вызовами клиента.
