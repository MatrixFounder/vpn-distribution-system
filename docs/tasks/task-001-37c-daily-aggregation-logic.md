# Задача 001.37c: Суточная агрегация и пересчёт

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-04 Учёт трафика и списание с коэффициентом

Требования RTM: R-20, R-22.

<!-- contract:goal -->

## Цель задачи

Реализовать суточную агрегацию `traffic_daily` и её пересчёт после позднего отчёта. Часть
выделена из 001.37 по правилу 4 «Цикла задачи» (решение заказчика 2026-10-25, В-47).

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `control-plane/tests/e2e/test_daily_aggregate.py` — ночной пересчёт агрегата, агрегат суток равен сумме часов (TC-E2E-01, TC-E2E-02)
- `control-plane/tests/unit/accounting/test_aggregate.py` — идемпотентность агрегации (TC-UNIT-01)

### Изменения в существующих файлах

#### Файл: `control-plane/app/accounting/aggregate.py`

- `aggregate_day(conn, day)`: `traffic_daily` из `traffic_hourly`; повторный запуск идемпотентен; ночной проход пересчитывает сутки D−1…D−3 (окно приёма 72 ч) — так поздний отчёт не теряется, если его постановка `aggregate:{day}` пришлась на время, когда задача этих суток в `running` (дубль ключа подавляется и для `running`)

#### Файл: `control-plane/app/jobs/handlers/__init__.py`

- тип `traffic.aggregate_day` (полезная нагрузка `{"day"}`, ключ `aggregate:{day}`; её же ставит поздний отчёт 001.77b)

#### Файл: `control-plane/app/jobs/scheduler.py`

- расписание: агрегация 00:10 UTC (смещение `Periodic.offset` — 001.37)

### Интеграция компонентов

Задачу `traffic.aggregate_day` ставит поздний отчёт 001.77b; задачи, поставленные до приёмки этой,
ждут в `pending`, пока тип не зарегистрирован здесь. Срок хранения `traffic_daily` (24 месяца,
Н-21) применяет `retention.purge` 001.37.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Ночной пересчёт D−1…D−3
   - Входные данные: поздний отчёт суток D−2 принят, пока задача `aggregate:{D−2}` в `running` (постановка подавлена ключом); затем ночной проход 00:10 UTC следующих суток
   - Ожидаемый результат: ночной проход пересчитал свои сутки D−1…D−3, в том числе сутки отчёта (для него — D−3); `traffic_daily` этих суток включает поздний отчёт
2. **TC-E2E-02:** Агрегат суток равен сумме часов
   - Входные данные: строки `traffic_hourly` пользователя на ноде за сутки D — две строки часа 10:00 разных пар «группа × коэффициент» и строка часа 23:00; строка часа 00:00 суток D+1; `aggregate_day(conn, D)`
   - Ожидаемый результат: строка `traffic_daily` (пользователь, нода, D): `raw_uplink_bytes`, `raw_downlink_bytes` и `billable_bytes` равны суммам трёх строк суток D; строка суток D+1 не вошла

### Модульные тесты

1. **TC-UNIT-01:** Идемпотентность агрегации
   - Проверяемая функция: `app/accounting/aggregate.py::aggregate_day`
   - Входные данные: двойной запуск
   - Ожидаемый результат: `traffic_daily` без дублей

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/e2e/test_daily_aggregate.py tests/unit/accounting/test_aggregate.py tests/unit/jobs/test_queue.py`
- Полный набор: `make test` — существующие тесты проходят.

## Критерии приёмки

- [ ] Строка `traffic_daily` «пользователь × нода × сутки» равна сумме строк `traffic_hourly`
  этих суток (raw и billable; TC-E2E-02); повторный запуск `aggregate_day` строк не дублирует
  (TC-UNIT-01)
- [ ] Поздний отчёт входит в `traffic_daily` своих суток постановкой `aggregate:{day}` или
  ночным пересчётом D−1…D−3, в том числе когда постановку подавила задача суток в `running`
  (TC-E2E-01)
