## Цель задачи

Довести развёртывание до §10.3–§10.4 архитектуры в части Compose: промышленный Compose, три
`server` nginx с правилами границы mTLS, Docker secrets; домены подписки — из одного списка
окружения развёртывания (В-27). Публичный `server` и ACME — 001.66b, отказ отозванному сертификату
на прокси — 001.66c, офлайн-CA серверных сертификатов — 001.66d, DNS-записи доменов и домена писем
— 001.66e (дробление по В-47 а, 2026-10-25).

## Примечания

Конфигурационная задача.

Пункты «решить здесь» прежней 001.66 разнесены при дроблении (В-47 а, 2026-10-25): публичный
`server`, временные файлы тел, пределы до запроса, страницы ошибок — 001.66b; `ssl_crl` и карта
отказа, возобновление TLS-сессий, исключение `dev/dev-node.crt` — 001.66c; профиль CA, серверные
сертификаты, офлайн-CA и сторона C-01 при разделении CA — 001.66d.

Найдено при 001.33 (заглушки), решить здесь:

- промышленный профиль Compose обязан сохранить tmpfs временных файлов nginx (весь
  `/var/cache/nginx` — `client_body_temp_path` и `proxy_temp_path` — tmpfs 64 МиБ под потолком
  памяти с правами 0711 на точке монтирования: мастер nginx создаёт подкаталоги рабочему
  процессу, которому нужен проход, с 0700 он получал Permission denied — стенд раунда 8; тела
  Node API туда не попадают — 411 на тела без длины, буферы равны пределам; ответы апстрима
  сверх буферов — до `proxy_max_temp_file_size` 8 МиБ на ответ, 64 МиБ = восемь таких; тела
  пишет только публичный server), `worker_processes` nginx равным квоте `cpus`, потолки
  процессора и числа процессов (`cpus`, `pids_limit`) и предел журналов (`json-file`, 10 МиБ ×
  3) базового файла; страж `test_proxy_contract.py` читает список файлов Compose из команды
  запуска в шапке базового файла, сверяет её с `deploy/README.md` и отвергает любой другой
  `*.y*ml` в каталоге, `include:` и `extends:` — промышленный оверлей получает свою команду
  (базовый файл и `docker-compose.prod.yml`, в шапке и в README), страж разбирает каждую команду
  отдельно; оверлей не переопределяет пределы памяти, `cpus`/`pids_limit`, `logging` и тома
  nginx; deployment.md §10.4 описывает это.
