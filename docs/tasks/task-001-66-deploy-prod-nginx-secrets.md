## Примечания

Конфигурационная задача.

Найдено при 001.33 (заглушки), решить здесь:

- у `api` (1g) и `nginx` (256m) в Compose стоят `mem_limit` = `memswap_limit` (001.33):
  превышение — OOM-kill контейнера, а политики перезапуска в файлах Compose нет (`restart:`
  не задан) — до этой задачи контейнер после OOM остаётся остановленным; ввести
  `restart: unless-stopped` (или эквивалент оркестратора) для всех ролей и алерт на
  перезапуски (001.68);
- публичный `server` nginx (80/443) не имеет ни `limit_conn`, ни `limit_req` и делит
  `worker_connections` с агентским: анонимный клиент может выбрать соединения, на которых
  держатся пределы Node API — задать пределы по адресу источника здесь или в 001.72;
- промышленный профиль Compose обязан сохранить tmpfs временных файлов nginx (весь
  `/var/cache/nginx` — `client_body_temp_path` и `proxy_temp_path` — tmpfs 64 МиБ под потолком
  памяти с правами 0711 на точке монтирования: мастер nginx создаёт подкаталоги рабочему
  процессу, которому нужен проход, с 0700 он получал Permission denied — стенд раунда 8; тела
  Node API туда не попадают — 411 на тела без длины, буферы равны пределам; ответы апстрима
  сверх буферов — до `proxy_max_temp_file_size` 8 МиБ на ответ, 64 МиБ = восемь таких; тела
  пишет только публичный server), `worker_processes` nginx равным квоте `cpus`, потолки
  процессора и числа процессов (`cpus`, `pids_limit`) и предел журналов (`json-file`, 10 МиБ ×
  3) базового файла; страж `test_proxy_contract.py` читает список файлов Compose из команды
  запуска в шапке базового файла, сверяет её с `deploy/README.md` и отвергает любой другой
  `*.y*ml` в каталоге, `include:` и `extends:` — промышленный оверлей добавляется в ту же
  команду (и в README) и не переопределяет пределы памяти, `cpus`/`pids_limit`, `logging` и
  тома nginx; deployment.md §10.4 описывает это;
- публичный `server`: таймауты клиента и апстрима, набор шифров, порт 80 (редирект на 443 или
  закрытие), пределы соединений и тела по адресу источника (сегодня 1 МиБ с буфером 16k — тела
  больше буфера идут в tmpfs; медленное чтение ответа держит соединение с прокси и место в tmpfs
  до 8 МиБ — при заполнении nginx отвечает 500 тому запросу, которому не хватило места; отчёты и
  enrollment не затронуты) — здесь.

Зависимости: 001.02, 001.25. Приоритет: Critical. Оценка: 4 ч. Этап: 11 — эксплуатация.
- отдельный каталог временных файлов (свой tmpfs или `client_body_temp_path` уровня server)
  под тела публичного server: сегодня он общий с временными файлами ответов Node API, и
  анонимные медленные заливки на публичный server (64 × 1 МиБ) могут оставить снапшот состава
  без места — 500 ноде (роаст раунда 8; пробой не воспроизведено); размер под парк — с
  потолком снапшота из 001.75; запас `worker_connections` (1 024 на один worker, общие у трёх
  server) от анонимных соединений при `client_header_timeout 5s`; `listen [::]:8444` — IPv6.
