# Задача 001.16: API кабинета: логика профиля, статистики, перевыпуска токена, онбординга

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-02 Регистрация и активация подписки Redeem-кодом
- UC-16 Работа в личном кабинете

Требования RTM: R-09, R-10, R-11, R-12, R-52.

<!-- contract:goal -->

## Цель задачи

Реализовать чтение состояния подписки, статистику из `traffic_hourly`, маршрут перевыпуска токена
(перевыпуск и ротация credentials — 001.42), данные мастера первого подключения с проверкой
соединения, показатель времени до первого подключения и повторную отправку письма подтверждения.

- окно периода — функция окна периода 001.77c (её вводит 001.77c, статистика её переиспользует и
  своей не заводит): правило периода списания модели данных («Период списания строки отчёта») —
  момент относится к последнему по `created_at` периоду пользователя, у которого
  `min(period_start, created_at)` не позже этого момента (решение заказчика 2026-10-25, В-1).
  Час `traffic_hourly` относится к окну, в котором лежит его `hour_start`: трафик до досрочного
  продления относится к прежнему периоду, после — к новому. Списание относит к периоду каждую
  часть по её `period_start`, статистика — час целиком, поэтому в час продления статистика
  кабинета расходится с балансом периода не больше чем на трафик одного часа
- `limit` — действующий лимит периода, функция `effective_limit` (001.42; те же значения отдаёт `subscription-userinfo`, В-25): `traffic_limit_bytes` плюс сумма начислений (`bonus`, `adjustment`) того же периода, взятая со знаком минус (начисление — отрицательная дельта `balance_entries`, решение 001.22); считать его как `remaining + billable` нельзя: при перерасходе `remaining` упирается в ноль (Н-17б)
- `remaining` — `remaining_of(traffic_limit_bytes, used_billable_bytes)`
- описания полей и docstring: `limit` — действующий лимит, `remaining` — `remaining_of`; коэффициент кратен 0.1 (`multiplier_milli % 100 = 0`)

### Интеграция компонентов

Статистика читает `traffic_hourly`; число активных адресов — функция 001.38 (зависимость 001.16 →
001.38). Перевыпуск целиком выполняет `SubscriptionTokenService.reissue` (001.42): отзыв прежнего
токена, новый токен и ротация credentials через `CompositionService.rotate_user_credentials`
(001.29); маршрут кабинета публикацию состава не ставит. Контекст аудита — `AuditContext` (001.46,
зависимость 001.16 → 001.46); `audit.record` перевыпуска вызывает `reissue` (001.42). Действующий
лимит — `effective_limit` (001.42). Отметку первого подключения ставит приём отчёта (001.77) в своей
транзакции; проверка соединения читает `user_online_ips`, которую пишет тот же приём. Окно периода
статистики — функция окна периода 001.77c, правило отнесения списания к периоду. Язык и строки
текстов ответов — `negotiate` и файлы `locales/` (001.65, зависимость 001.16 → 001.65). Пометку
`users.email_undeliverable_at` эта задача только читает: колонку заводит 001.51 (зависимость 001.16
→ 001.51), ставит и снимает 001.78, показывает кабинет 001.63.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Статистика отражает фикстуры
   - Входные данные: две строки `traffic_hourly` на нодах с коэффициентами 1.0 и 2.0
   - Ожидаемый результат: `raw` и `billable` по нодам совпадают; остаток вычислен
2. **TC-E2E-02:** Перевыпуск ротирует credentials
   - Входные данные: `POST /me/subscription/reissue?confirm=true`
   - Ожидаемый результат: ответ — `SubscriptionOut` с новыми ссылками; прежний токен → 404; `node_user_credentials.version` увеличен для всех нод пользователя; одна строка `audit_log` перевыпуска с `actor_type = user`, `actor_id` пользователя, пустыми `ip` и `user_agent`
   - Примечание: AC-35
3. **TC-E2E-03:** Удалённый и заблокированный пользователь
   - Входные данные: действующая сессия пользователя с `users.status = 'deleted'`; действующая сессия пользователя с `users.status = 'blocked'`
   - Ожидаемый результат: `GET /me` → 401 `unauthenticated` в обоих случаях
4. **TC-E2E-04:** Повторная отправка письма подтверждения
   - Входные данные: `POST /auth/verify-resend` для неподтверждённого адреса четыре раза за час; для неизвестного адреса
   - Ожидаемый результат: первые три — 202 и новое письмо с действующей ссылкой; четвёртый — отказ по порогу §5.12; для неизвестного адреса — 202 без письма
5. **TC-E2E-05:** Проверка соединения и первое подключение
   - Входные данные: активированная подписка без подключений; затем принятый отчёт с адресом пользователя; второй отчёт
   - Ожидаемый результат: `check.status` = `failed`, затем `ok`; `first_connected_at` поставлен первым отчётом и вторым не изменён; гистограмма показателя получила одно наблюдение
6. **TC-E2E-06:** Досрочное продление
   - Входные данные: трафик в `traffic_hourly` до продления и после него; `renew` до окончания периода
   - Ожидаемый результат: `GET /me/subscription` показывает в новом периоде только трафик после продления
7. **TC-E2E-07:** Тексты на языке профиля
   - Входные данные: пользователь с профилем `ru` и подпиской `suspended_quota`;
     `GET /me/subscription` с `Accept-Language: en`; тот же запрос после `PATCH /me` с языком `en`
   - Ожидаемый результат: `reason` — строка ключа причины `suspended_quota` из `locales/ru.json`,
     после смены языка — из `locales/en.json`; заголовок запроса язык ответа не меняет (AC-22 в
     части ответов API); тексты мастера, которые отдаёт API, проверяются тем же способом
8. **TC-E2E-08:** Пометка недоставляемого адреса
   - Входные данные: `users.email_undeliverable_at` пользователя заполнена фикстурой теста (пометку
     ставит 001.78); затем очищена
   - Ожидаемый результат: `GET /me` отдаёт `email_undeliverable_at`, равное значению колонки, в
     ISO 8601 UTC; после очистки — `null`

### Модульные тесты

1. **TC-UNIT-01:** Агрегация по стране
   - Проверяемая функция: `app/accounting/stats.py::user_traffic`
   - Входные данные: строки по двум нодам одной страны
   - Ожидаемый результат: суммы по стране равны сумме по нодам
2. **TC-UNIT-02:** Действующий лимит при начислении
   - Проверяемая функция: `app/accounting/stats.py::user_traffic`
   - Входные данные: лимит тарифа L; начисление `bonus` объёмом B в журнале периода; списано больше L + B
   - Ожидаемый результат: `limit` = L + B; `remaining` = 0
3. **TC-UNIT-03:** Окно периода и час продления
   - Проверяемая функция: `app/accounting/stats.py::user_traffic` (окно — функция 001.77c)
   - Входные данные: период с `created_at` раньше `period_start` (досрочное продление в момент T внутри часа H); строки `traffic_hourly` за час до H, за час H и за час после H
   - Ожидаемый результат: строки до H и строка часа H — в прежнем периоде (её `hour_start` раньше T), строка после H — в новом; новый период строку часа H не содержит
