# Задача 001.80: Node Agent: применение конфигурации с перезапуском и горячее применение состава

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-01 Ввод ноды в эксплуатацию
- UC-05 Исчерпание лимита и отзыв доступа

Требования RTM: R-04.

<!-- contract:goal -->

## Цель задачи

Реализовать применение потока конфигурации (запись `/etc/xray/config.json`, финальное чтение
счётчиков, `systemctl restart xray`, новый `counter_epoch`, возврат состава, переустановка правил),
раздела `agent` без перезапуска Xray и потока состава (`AddUser`/`RemoveUser` без перезапуска по
тегу `xray_email` строки; удаление отсутствующих — только по ответу с `users.full = true`, а не по
факту запроса `full=1`).

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `node-agent/internal/sync/apply_test.go` — mock Xray: вызовы `AlterInbound`; перезапуск только при смене конфигурации

### Изменения в существующих файлах

#### Файл: `node-agent/internal/sync/apply_config.go`

- реализация; перезапуск Xray — только при смене `config.checksum` документа Xray
- раздел `agent` (параметры агента вне документа Xray) применяется без перезапуска Xray: запись в
  Store, перезагрузка набора nftables (001.86); стратегию разрыва и коэффициент читают 001.60 и
  001.57
- после каждого старта Xray (применение конфигурации, `restart_xray`, перезапуск systemd после
  сбоя, перезагрузка VPS; признак — сброс времени работы процесса, `Uptime`, 001.56) агент через
  `AlterInbound` добавляет всех пользователей локального состава в состоянии `active`, кроме
  исчерпавших грант локально (001.57), затем переустанавливает правила маршрутизации 001.58 и
  001.82 (если PoC-1а 001.88 выбрал `route_block`): inbound в `config.json` приходят без
  пользователей

#### Файл: `node-agent/internal/sync/apply_users.go`

- реализация; вызов стратегии разрыва для состояний, снимающих доступ (001.60)
- строка применяется по `xray_email` из строки; локальный состав (строки потока состава)
  хранится в Store, соответствие «тег → `user_id`» для отчёта берётся из него, а не разбором тега
- `removed` — удаление пользователя из inbound и из локального состава
- удаление отсутствующих — только по ответу с `users.full = true`; снапшот, урезанный вентилем по
  статусу ноды (`users.full = false`), никого не удаляет

#### Файл: `node-agent/internal/xray/client.go`

- `HandlerService`: `AddUser`, `RemoveUser` (`AlterInbound`) — реализация; `AddInbound` и
  `RemoveInbound` не нужны: `restart_inbound` выбран быть не может (решение заказчика 2026-10-25,
  В-9)

### Интеграция компонентов

Финальное чтение — 001.56; правила — 001.58; разрыв — 001.60. Раздел `agent`: контракт — 001.26,
приём — 001.55.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Состав применяется горячо
   - Входные данные: дельта с двумя пользователями
   - Ожидаемый результат: `AddUser` дважды; перезапуска Xray нет (AC-32)
2. **TC-E2E-02:** Конфигурация с перезапуском
   - Входные данные: новая `config_version`
   - Ожидаемый результат: финальный отчёт отправлен; Xray перезапущен; пользователи состава
     возвращены в inbound; правила переустановлены
3. **TC-E2E-03:** Полный ответ удаляет лишних
   - Входные данные: ответ с `users.full = true` без пользователя, который есть в Xray
   - Ожидаемый результат: `RemoveUser` вызван
4. **TC-E2E-04:** Неполный снапшот никого не удаляет
   - Входные данные: ответ на `full=1` с `users.full = false` (фильтрующий статус ноды)
   - Ожидаемый результат: `RemoveUser` не вызван
5. **TC-E2E-05:** Возврат состава после сбоя Xray
   - Входные данные: перезапуск Xray без смены курсоров (сбой процесса)
   - Ожидаемый результат: пользователи `active` снова в inbound; исчерпавшие грант локально — нет
6. **TC-E2E-06:** Раздел `agent` без перезапуска
   - Входные данные: новая версия раздела `agent`, `config.checksum` прежний
   - Ожидаемый результат: перезапуска Xray нет; значения раздела в Store

### Модульные тесты

1. **TC-UNIT-01:** Строка применяется по `xray_email`
   - Проверяемая функция: `internal/sync::applyRow`
   - Входные данные: строка `active` с `xray_email` и `user_id`
   - Ожидаемый результат: `AddUser` с тегом `xray_email` строки; отчёт несёт `user_id` строки
2. **TC-UNIT-02:** Строка `removed`
   - Проверяемая функция: `internal/sync::applyRow`
   - Входные данные: строка `removed` пользователя, который есть в inbound
   - Ожидаемый результат: `RemoveUser` вызван; пользователь удалён из локального состава

### Регрессионные тесты

- Команда: `cd node-agent && go test ./internal/sync/... -run Apply`
- Полный набор: `make test` — существующие тесты проходят.
