# Задача 001.64: Web: экраны панели — дашборд, пользователи, ноды, тарифы, коды, аудит

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-09 Управление тарифами, группами и кодами
- UC-13 Поддержка пользователя
- UC-07 Отказ и возврат ноды

Требования RTM: R-34, R-38, R-53.

<!-- contract:goal -->

## Цель задачи

Реализовать экраны разделов §4.15 источника для настольного экрана с таблицами, фильтрами,
карточками ноды и пользователя (данные §17.5), формами настроек и чтением аудита.

### Новые файлы

### Изменения в существующих файлах

#### Файл: `web/apps/admin/src/pages/*`

- реализация; вход с TOTP; действия с подтверждением; отображение `desired/applied` ноды и `error_state` inbound
- действия, недоступные роли, скрыты по списку разрешений `GET /admin/auth/session` (001.46)
- карточка пользователя: кнопка «Показать ссылку» — запрос `GET /admin/users/{id}/subscription-url` только по нажатию, без кеширования ответа
- экран нод: после выдачи bootstrap-токена показывается `bootstrap_command` из ответа (001.61) с копированием; повторно не показывается
- экран нод: изменение записи ноды и вывод из эксплуатации (маршруты — 001.87)
- карточка пользователя (решения заказчика 2026-10-25): «Заблокировать» — одно действие с
  обязательной причиной (В-40); «Подтвердить адрес» для неподтверждённого адреса (В-32); пометка
  недоставляемого адреса `email_undeliverable_at` (В-37); «Работа от лица пользователя» —
  `POST …/impersonate`, расширенная карточка из `GET …/impersonate` без действий изменения,
  «Завершить» — `DELETE …/impersonate` (В-36)
- карточка пользователя: корректировка баланса в обе стороны (решение заказчика 2026-10-25, В-4) —
  начисление (`POST …/traffic` с положительным значением) и уменьшение (`POST …/traffic` с
  отрицательным значением, маршрут 001.50 вызывает `SubscriptionService.deduct_traffic`); у
  уменьшения поле причины обязательно: без причины форма запрос не отправляет, ответ 422
  `reason_required` показывается у поля причины
- карточка ноды: команды ноды и их результаты (В-18) — список `GET /admin/nodes/{id}/commands`
  (тип, статус, `issued_at`, `expires_at`) и экран команды
  `GET /admin/nodes/{id}/commands/{command_id}`: нагрузка, статус, текст ошибки и `output` результата
  `collect_diagnostics` как текст без интерпретации разметки (маршруты — 001.31)
- второе подтверждение (В-34): ответ 202 `approval_required` показывается как «ожидает
  подтверждения»; список `GET /admin/approvals` с кнопкой «Подтвердить»
- настройки: пункт «обслуживание» — действующие окна, создание и снятие окна
  (`/admin/settings/maintenance`, 001.85; В-50); домены подписки — только чтение (В-27); пороги
  второго подтверждения `approval.traffic_bytes` (объём за операцию) и `approval.renew_days`
  (дни продления) — поля формы `PATCH /admin/settings` (ключи — 001.48, сохранение — 001.85);
  пустое поле — порог выключен (`null`, по умолчанию; В-34)
- раздел Administrators (`/admin/admins`, 001.89; В-33, В-35) — для Super Admin: список,
  создание учётной записи, смена роли, блокировка, сброс пароля и второго фактора; свой профиль
  (каждая роль) — смена пароля, перевыпуск TOTP с подтверждением кодом нового секрета, выход на
  всех устройствах. Пароль, URI провижининга TOTP и резервные коды из ответа показываются один раз
  и повторно не показываются; в своём профиле — выбор языка панели (`PATCH /admin/admins/me`,
  001.89)
- язык панели — поле `language` ответа `GET /admin/auth/session` (001.46, 001.89), а не язык
  пользователей (idea §17.8); после смены языка в своём профиле строки панели меняются без
  повторного входа

### Интеграция компонентов

Данные — `/api/v1/admin/*` (001.50). Поле `bootstrap_command` ответа выдачи токена собирает 001.61.
Экраны изменения и вывода ноды — зависимость от 001.87; раздел Administrators и свой профиль —
зависимость от 001.89. Время экраны выводят только через `formatDateTime` (001.65b); пояс
отображения в панели — по ответу на вопрос «решить здесь» 001.65b.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Карточка пользователя
   - Входные данные: открыть пользователя
   - Ожидаемый результат: поля §17.5 отображены (AC-27)
2. **TC-E2E-02:** Второй фактор
   - Входные данные: вход
   - Ожидаемый результат: поле кода TOTP обязательно
3. **TC-E2E-03:** Действия по роли
   - Входные данные: сессия `support` (mock `GET /admin/auth/session`); открыть раздел тарифов
   - Ожидаемый результат: кнопки изменения и удаления тарифа не показаны
4. **TC-E2E-04:** Показ subscription URL
   - Входные данные: открыть карточку пользователя, затем нажать «Показать ссылку»
   - Ожидаемый результат: до нажатия запроса `subscription-url` нет; после — ссылки на обоих
     доменах
5. **TC-E2E-05:** Bootstrap-команда
   - Входные данные: выдача токена для ноды (mock ответа)
   - Ожидаемый результат: команда с токеном и адресами показана
6. **TC-E2E-06:** Работа от лица пользователя
   - Входные данные: «Работа от лица пользователя», затем «Завершить» (mock ответов)
   - Ожидаемый результат: запросы `POST`, `GET`, `DELETE …/impersonate` по порядку; на экране
     режима нет кнопок изменения
7. **TC-E2E-07:** Операция сверх порога
   - Входные данные: начисление трафика, mock ответа 202 `approval_required`
   - Ожидаемый результат: показано «ожидает подтверждения»; запрос виден в списке подтверждений
8. **TC-E2E-08:** Раздел Administrators и свой профиль
   - Входные данные: сессии `admin` и `super_admin` (mock `GET /admin/auth/session`); перевыпуск
     TOTP в своём профиле (mock ответа с URI и резервными кодами), затем повторное открытие экрана
   - Ожидаемый результат: у `admin` пункта раздела нет, свой профиль доступен; у `super_admin` —
     список учётных записей; URI и коды показаны один раз, при повторном открытии их нет
9. **TC-E2E-09:** Корректировка баланса в обе стороны
   - Входные данные: карточка пользователя; начисление 5 ГБ; уменьшение 2 ГБ без причины; то же с
     причиной; mock ответа 422 `reason_required`
   - Ожидаемый результат: начисление — запрос `POST …/traffic` с положительным значением; уменьшение
     без причины — запроса нет, поле причины отмечено; с причиной — запрос с отрицательным значением
     и `reason`; ответ 422 показан у поля причины
10. **TC-E2E-10:** Команды ноды
    - Входные данные: карточка ноды; mock списка команд и команды `collect_diagnostics` с `output`,
      содержащим `<script>`
    - Ожидаемый результат: список команд показан; экран команды показывает `output` текстом, без
      исполнения разметки
11. **TC-E2E-11:** Пороги второго подтверждения
    - Входные данные: настройки с `approval.traffic_bytes = null` и `approval.renew_days = 30`
      (mock `GET /admin/settings`); ввод порога 100 ГБ и очистка поля дней
    - Ожидаемый результат: поле объёма пусто («выключен»), поле дней — 30;
      `PATCH /admin/settings` с `approval.traffic_bytes` в байтах и `approval.renew_days = null`
12. **TC-E2E-12:** Язык панели
    - Входные данные: сессия с `language = ru` (mock `GET /admin/auth/session`); смена языка на
      `en` в своём профиле
    - Ожидаемый результат: строки панели — RU; после смены — запрос `PATCH /admin/admins/me` и
      строки EN без повторного входа
