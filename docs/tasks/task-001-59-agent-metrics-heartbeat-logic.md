# Задача 001.59: Node Agent: heartbeat, метрики ОС и Xray, экспорт для Control Plane

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-07 Отказ и возврат ноды

Требования RTM: R-05, R-45.

<!-- contract:goal -->

## Цель задачи

Реализовать heartbeat раз в 30 с с джиттером (версии, время ноды, применённые курсоры, состояние
процесса Xray), сбор CPU, памяти, диска, сети, числа уникальных адресов онлайн (Xray), соединений
(ОС) и времени работы ноды и агента, отправку метрик раз в 60 с, проверку доступности
`reality_target` каждого inbound из сети ноды.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `node-agent/internal/metrics/metrics_test.go` — heartbeat не пропускается при занятом цикле отчётов
- `node-agent/internal/metrics/targets.go` — проверка доступности `reality_target` каждого inbound
  из сети ноды (`docs/idea.md` §4.4, §4.7, Н-30): TLS 1.3, HTTP/2, без перенаправления; цели — из
  применённой конфигурации; раз в час и после применения новой конфигурации, в том числе первой
  (ввод ноды в эксплуатацию)

### Изменения в существующих файлах

#### Файл: `node-agent/internal/metrics/collect.go`

- `/proc` и `GetStatsOnline`; соединения через `ss -s` или `/proc/net/sockstat`
- heartbeat несёт `agent_version`, `xray_version`, `node_time` (часы ноды со смещением) и
  применённые курсоры `applied_config_version`, `applied_users_seq` из Store (001.55)
- в теле heartbeat — `xray_running`: Xray ответил на `GetSysStats` (`Uptime`, 001.56); §4.7
  `docs/idea.md` «Состояние процесса Xray», от него зависят переход `provisioning` → `active` и
  `degraded` «Процесс Xray не запущен» (001.30)
- в теле метрик — `uptime_s` (время работы ноды, `/proc/uptime`) и `agent_uptime_s` (время работы
  процесса агента), в секундах; §4.7 «Время работы ноды и агента». Имена и место полей — контракт
  001.30
- признака неизвестного обязательного раздела heartbeat не несёт: ответ без известного
  обязательного раздела агент не применяет и повторяет запрос (001.55), нода в `degraded` по этой
  причине не переводится (решение заказчика 2026-10-25, В-14)
- результат проверки целей — раздел `targets[]` (`inbound_tag`, `ok`, `reason`) тела метрик
- накопительные счётчики агента с момента запуска — сброшенные отчёты буфера
  `buffer_dropped_reports`, убывания счётчиков `counter_decreases`, смещение часов
  `clock_offset_ms`, отказы отчёта по коду `report_rejects` (001.56), сумма и число
  `disconnect_seconds` (001.60) — в теле метрик; имена — контракт 001.30

### Интеграция компонентов

Heartbeat — отдельная горутина; не блокируется отправкой отчётов. Курсоры ведёт цикл
синхронизации 001.55 — эта задача от неё зависит. Тела heartbeat и метрик закрыты
`extra="forbid"`: поля `xray_running`, `uptime_s`, `agent_uptime_s`, `targets[]` и счётчики агента
вводит в контракт 001.30 (фикстуры `heartbeat.json`, `metrics.json`; приём `targets[]` передаёт
результат в 001.27) — эта задача от неё зависит. Поле `conn_stats[]` (счётчики conntrack по
адресам) и его отправку в теле метрик вводит 001.39 после этой задачи, локальный сбор — 001.86.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Heartbeat стабилен
   - Входные данные: 10 минут работы с загрузкой
   - Ожидаемый результат: интервалы 30 ± 3 с; Control Plane не переводит ноду в `offline`
2. **TC-E2E-02:** Курсоры в heartbeat
   - Входные данные: `Ack` новых курсоров циклом синхронизации
   - Ожидаемый результат: следующий heartbeat несёт новые `applied_config_version` и
     `applied_users_seq`

### Модульные тесты

1. **TC-UNIT-01:** Разбор `/proc/stat`
   - Проверяемая функция: `internal/metrics::cpuPercent`
   - Входные данные: две выборки
   - Ожидаемый результат: процент в [0, 100]
2. **TC-UNIT-02:** Проверка цели REALITY
   - Проверяемая функция: `internal/metrics::checkTarget`
   - Входные данные: тестовые серверы: TLS 1.3 с HTTP/2; TLS 1.2; ответ с перенаправлением
   - Ожидаемый результат: `ok` для первого; `ok = false` с причиной для двух других
3. **TC-UNIT-03:** Состояние процесса Xray
   - Проверяемая функция: `internal/metrics::Collect`
   - Входные данные: mock Xray отвечает на `GetSysStats`; затем недоступен (процесс остановлен)
   - Ожидаемый результат: `xray_running = true`; затем `xray_running = false`; тело метрик в обоих
     случаях несёт `uptime_s` и `agent_uptime_s`

### Регрессионные тесты

- Команда: `cd node-agent && go test ./internal/metrics/...`
- Полный набор: `make test` — существующие тесты проходят.
