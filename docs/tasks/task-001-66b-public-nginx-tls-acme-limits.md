# Задача 001.66b: Публичный server nginx: TLS, порт 80 и ACME, раздача web, пределы

Тип задачи: `[CONFIGURATION]`.

- UC-16 Работа в личном кабинете

## Цель задачи

Довести публичный `server` nginx до §10.4 архитектуры и security.md §7.2–§7.3: TLS (HSTS, CSP,
TLS 1.2+, набор шифров, таймауты), ACME, порт 80 — 301 на 443, кроме запроса ACME, кабинет и панель
— контейнер `web` (C-04) за `proxy_pass`, пределы соединений и частоты публичного `server`,
отдельный каталог временных файлов его тел, запас `worker_connections`, IPv6. Раздача интерфейса и
ACME — техническое решение OPS-03 (`docs/reviews/wi-35-spec-review.md`): nginx файлов не отдаёт
(Н-25), страж прокси не меняется. Владелец пределов публичного `server` — эта задача (security.md
§7.3; OPS-05, PLAN-14); пороги приложения — 001.72.

## Примечания

Конфигурационная задача.

ACME DNS-01 — допустимая замена HTTP-01 по техническому решению OPS-03: тогда служба `certbot` за
портом 80 и location ACME не нужны; способ фиксируется до кода (правило 1 «Цикла задачи»).

Найдено при 001.33 (заглушки), решить здесь:

- публичный `server`: таймауты клиента и апстрима, набор шифров, предел тела (сегодня 1 МиБ с
  буфером 16k — тела больше буфера идут в tmpfs; медленное чтение ответа держит соединение с
  прокси и место в tmpfs до 8 МиБ — при заполнении nginx отвечает 500 тому запросу, которому не
  хватило места; отчёты и enrollment не затронуты) — здесь; порт 80 и пределы соединений — в
  «Описании изменений»;
- отдельный каталог временных файлов (свой tmpfs или `client_body_temp_path` уровня server)
  под тела публичного server: сегодня он общий с временными файлами ответов Node API, и
  анонимные медленные заливки на публичный server (64 × 1 МиБ) могут оставить снапшот состава
  без места — 500 ноде (роаст раунда 8; пробой не воспроизведено); размер под парк — с
  потолком снапшота из 001.75b; запас `worker_connections` (1 024 на один worker, общие у трёх
  server) от анонимных соединений при `client_header_timeout 5s`; `listen [::]:8444` — IPv6.

Найдено при 001.25, раунд 4 (решить здесь):

- отказы, которые nginx выносит при разборе заголовков, раньше всех фаз, пределов
  `limit_req`/`limit_conn` не знают: 400 (разбор, негодный `Host`, `Content-Length` вместе с
  `Transfer-Encoding`, HTTP/1.0 с `Transfer-Encoding`, сбой или отсутствие клиентского
  сертификата на 8443, HTTP без TLS на порт TLS), 405 (`TRACE`, `CONNECT`), 408 (заголовки не дошли за
  `client_header_timeout`), 414, 494, 501 (неизвестный `Transfer-Encoding`). Стенд 001.25: залпы по 30 параллельных запросов — 30 × 400 (негодный
  `Host`; без сертификата на 8443), 30 × 405, 30 × 501 без единого 429; по HTTP/1.1 каждый такой
  отказ закрывает соединение. Отказы, которые решает сама конфигурация (404, 411, 413), с 001.25
  идут после пределов (`try_files`; 413 — картой длины до FIND_CONFIG, раунд 5 роаста), но журнал
  от анонимного залпа пределы nginx не защищают: сток, объём и срок журнала прокси — 001.68
  (security.md §7.2); предел соединений и запросов на соединение с адреса до HTTP — здесь
  (`keepalive_requests` на server Node API, предел соединений на уровне хоста); 413 на 8443/8444
  — страница nginx, не единый формат (контракт README это оговаривает).

Найдено при 001.25, раунд 9 роаста (решить здесь):

- **медленный клиент страницы подписки держит запрос `api`.** `location ^~ /s/` временных файлов
  ответа не пишет (`proxy_max_temp_file_size 0` — Н-25: строка error.log о записи временного
  файла несла бы токен), и ответ больше буферов прокси (8 × 4 КиБ на стенде) C-01 отдаёт со
  скоростью клиента; у публичного `server` нет предела соединений — анонимные медленные читатели
  подписки держат запросы `api` без счёта. Пределы соединений публичного `server` и
  `worker_connections` — в «Описании изменений»; размер ответа подписки против буферов — здесь
  (роаст 001.25, раунд 9);
- **переходы, меняющие `$uri`, запрещены стражем** (`test_only_the_service_rewrites_change_the_uri`):
  страницы ошибок публичного `server` (обычная `error_page 500 502 503 504 /50x.html;`) — только
  именованным location, иначе при лежащем api токен подписки ляжет в access.log и error.log
  (стенд 001.25, раунд 9).
