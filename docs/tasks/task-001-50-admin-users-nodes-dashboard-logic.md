## Цель задачи

Реализовать поиск и действия над пользователями, карточку с данными поддержки, карточку ноды с
метриками, дашборд и настройки с валидацией (домены ≥ 2, Н-25).

## Описание изменений

### Новые файлы

- `control-plane/tests/e2e/test_admin.py` — реальные утверждения; UC-13 A2 корректировка с причиной

### Изменения в существующих файлах

#### Файл: `control-plane/app/api/admin/users.py`

- поиск по адресу и идентификатору; действия через `SubscriptionService`, `CompositionService.rotate_credentials`; карточка из `subscription_access_log`, `node_user_state.updated_at`, `traffic_hourly`, `resale_signals`; корректировка баланса с причиной

### Интеграция компонентов

Все действия проходят `require_permission` и `audit.record`.

Передано из 001.84/001.14 (Н-27, пользовательская половина): блокировка учётной записи
(`users.status = 'blocked'`, interfaces.md §5.1 «`/admin/users` … блокировка») в той же
операции вызывает `SessionStore.revoke_all(user_id)` — сессии кабинета недействительны
немедленно (постановка допускает ≤ 60 с); `current_user` статус в базе не перепроверяет,
поэтому без этого вызова заблокированный продолжал бы работать в кабинете до истечения TTL
бездействия. Вход заблокированного уже закрыт (`authenticate` требует `status = 'active'`).
Тест: заблокировать пользователя с двумя живыми сессиями → `GET /api/v1/me` обеими → 401.
