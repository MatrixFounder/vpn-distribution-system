# Задача 001.58: Node Agent: блокировка адресов через RoutingService с переустановкой

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-08 Ограничение числа адресов и перепродажа доступа

Требования RTM: R-27.

<!-- contract:goal -->

## Цель задачи

Реализовать применение `blocked_ips[]` правилами `RoutingService` с сохранением в Store и
переустановкой после перезапуска Xray.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `node-agent/internal/guard/guard_test.go` — правило блокировки переустанавливается после перезапуска

### Изменения в существующих файлах

#### Файл: `node-agent/internal/guard/routing.go`

- `Apply(user string, blocked []netip.Addr)`: `AddRule`/`RemoveRule` с тегом `blk-{user}`; сохранение в Store; `Reapply()` после перезапуска

#### Файл: `node-agent/internal/xray/client.go`

- `RoutingService`: `AddRule`, `RemoveRule` — реализация

### Интеграция компонентов

Адреса приходят в строке потока состава (`blocked_ips`, применение строки — 001.80); `Reapply`
вызывается после каждого старта Xray (001.80). Набор nftables, лимит соединений с адреса (Н-29) и
счётчики conntrack — 001.86.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Блокировка адреса
   - Входные данные: строка состояния с `blocked_ips`
   - Ожидаемый результат: `AddRule`; после перезапуска Xray правило присутствует (AC-10)

### Модульные тесты

1. **TC-UNIT-01:** Apply и Reapply
   - Проверяемая функция: `internal/guard::Apply`
   - Входные данные: два адреса пользователя; затем пустой список; затем `Reapply()`
   - Ожидаемый результат: правило с тегом `blk-{user}` на оба адреса в Xray и в Store; после
     пустого списка правило снято в обоих; `Reapply()` устанавливает ровно правила из Store

### Регрессионные тесты

- Команда: `cd node-agent && go test ./internal/guard/...`
- Полный набор: `make test` — существующие тесты проходят.
