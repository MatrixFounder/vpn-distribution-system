# Задача 001.56: Node Agent: счётчики, эпохи, буфер SQLite, отчёты, синхронизация времени

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-04 Учёт трафика и списание с коэффициентом
- UC-10 Восстановление Control Plane из резервной копии

Требования RTM: R-19, R-20.

<!-- contract:goal -->

## Цель задачи

Реализовать чтение счётчиков без сброса по сетке ноды, вычисление дельт внутри `counter_epoch`,
персистентный буфер интервалов ≥ 24 часов, деление отчёта на части, отправку по порядку интервалов
(внутри интервала — по `report_seq`), обработку `last_accepted_seq` и отказов, финальное чтение
перед плановым перезапуском, контроль отклонения времени.

#### Файл: `node-agent/internal/accounting/collector.go`

  убываний (001.59); сбор адресов онлайн и счётчиков интерфейса ОС
- сетка снятия — минутные границы, сдвинутые на случайную фазу φ ∈ [0, 60) с: фаза выбирается
  один раз и хранится в Store, иначе парк после недоступности Control Plane отправляет отчёты
  синхронно; дополнительный срез в hh:00:00 UTC — интервал сетки, содержащий границу часа,
  делится на два, и оба уходят со следующей отправкой по сетке (задержка не больше 60 с, Н-17 не
  растёт). Так интервал не пересекает границу часа UTC: строка относится к часу `period_start`,
  коэффициент берётся на `period_start`, интервал Control Plane не делит
- штатный интервал — 60 с (обязанность агента, §5.9, Н-17); интервал длиннее — только дельта
  после перерыва снятия счётчиков, одним интервалом не дольше часа; перерыв дольше часа — новая
  эпоха, дельта перерыва не отправляется (объём оценивает сверка непрерывности, 001.37d); смен
  эпохи — не больше 48 за скользящие сутки (сверх потолка Control Plane удерживает часть)
- новая эпоха — при каждом старте Xray и после перерыва снятия дольше часа. Старт Xray
  распознаётся по сбросу времени работы процесса (`Uptime`, `GetSysStats`), а не только по
  убыванию счётчика: без пользователей в inbound счётчиков нет. Перезапуск Xray посередине
  интервала: прежняя эпоха закрывается последним успешно снятым интервалом (дельта от последнего
  снятия до перезапуска неизвестна и не выдумывается), новая начинается с момента старта Xray,
  если он известен, иначе с момента обнаружения; её первый интервал — до ближайшей границы
  сетки. Перезапуск агента при живом Xray эпоху не меняет: один интервал от последнего снятия, не
  дольше часа
- интервалы ноды монотонны и не перекрываются, в том числе через смену эпохи; `period_end` не
  позже часов сервера плюс 5 с (`future`); новый интервал — не старше 72 ч (`too_old`); первый
  интервал ноды — не раньше выдачи identity, не раньше суток назад (с допуском 5 с) и не раньше
  первого назначения ноды тарифицируемой группе (`before_anchor`)

#### Файл: `node-agent/internal/accounting/sender.go`

- слив буфера — по `period_start` интервалов, внутри интервала — по номеру части; `report_seq` —
  в пределах эпохи, с единицы; части идут последовательно (следующая — после ответа на
  предыдущую), части одного интервала — подряд; один запрос отчёта в полёте на ноду независимо от
  числа действующих сертификатов (в окне ротации Н-28 их два, и слив двумя сертификатами
  параллельно нарушил бы порядок частей); реакции клиента на 429, 503 и таймауты — 001.54
- 200 (часть принята или удержана — `held_anomaly`, превышение без списания; решение заказчика
  2026-10-25, В-4) и 200 с `duplicate: true` → удаление из буфера;
  недоступность → накопление
- 409 `rejected_time` и `interval_closed` → часть не повторять: номер остаётся пропущенным,
  отправка продолжается с `max(last_accepted_seq, номер отказанной части) + 1` (не с
  `last_accepted_seq + 1`: это тот же номер, и ключ идемпотентности лёг бы на другой интервал);
  интервал закрывается на сервере завершением, частью следующего интервала или через 25 часов
  после приёма последней части (закрытие по сроку — 001.37b); 403 `node_mismatch` → остановка
  отправки, ошибка в журнале
- 413, 422 «сверх предела» и 422 `too_wide` → часть никогда не примут: делить и не повторять как
  есть, деление — до первой отправки следующих частей; части деления продолжают ту же нумерацию

  число добавленных; часть из одной строки пользователя, снова получившая 413 или `too_wide`,

  400 — чинить на стороне агента, не повторять и не делить

3. **TC-E2E-03:** Внеплановый перезапуск
   - Входные данные: передача с остановкой процесса Xray (`kill`) посередине
   - Ожидаемый результат: новая эпоха; между эпохами — разрыв, объём от последнего снятия до сбоя
     не отправлен; повторного списания нет
