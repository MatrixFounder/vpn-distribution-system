# Задача 001.69: Правила использования при регистрации, обращения провайдера, `Suspended`

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-02 Регистрация и активация подписки Redeem-кодом
- UC-07 Отказ и возврат ноды

Требования RTM: R-48.

<!-- contract:goal -->

## Цель задачи

Довести §16 источника: сверку принятой версии правил с текущей при регистрации (обязательность
принятия и сохранение версии приняты в 001.14), процесс реакции на обращение провайдера с переводом
ноды в `suspended` и сопоставлением по времени и ноде, минимальный состав раскрываемых данных
(решение заказчика 2026-10-25, В-45): оператору — пользователи с трафиком на ноде в интервале
жалобы (идентификатор и объём по часам, без адресов); провайдеру — только факт приостановки и
принятые меры; жалоба — строка таблицы `provider_complaints` со сроком хранения.

## Описание изменений

### Новые файлы

- `control-plane/tests/e2e/test_privacy.py` — сверка версии правил; обращение провайдера → `suspended` + событие оператору; срок хранения обращений
- `control-plane/migrations/NNN_settings_aup.sql` и откат (NNN — следующий свободный номер): сид
  ключей `settings.aup` (`{version, url}`) и `settings.privacy_policy` (`{version, url}`) —
  значения из текстов заказчика (В-45)
- `control-plane/migrations/NNN_provider_complaints.sql` и откат: таблица `provider_complaints`
  в схеме `control_plane` — нода, интервал жалобы (`period_start`, `period_end`), ссылка на
  обращение провайдера, время получения, администратор, время записи; индекс по времени записи
  для удаления по сроку; адресов (источника и назначения) в таблице нет; функция
  `SECURITY DEFINER` (владелец `app_owner`) удаления строк старше 12 месяцев по `created_at` — по
  образцу функций удаления по срокам 001.37 (data-model §4.5, §4.6)
- `control-plane/app/domain/complaints.py` — регистрация обращения и выборка: пользователи с
  трафиком на ноде в интервале жалобы — идентификатор пользователя и объём по часам из
  `traffic_hourly` (срок хранения почасовых записей — 90 дней, Н-21: за более старый интервал
  выборка пуста)

### Изменения в существующих файлах

#### Файл: `control-plane/app/api/admin/nodes.py`

- `POST /admin/nodes/{id}/provider-complaint` (заглушка — 001.49): в одной транзакции — строка
  `provider_complaints`, перевод ноды в `suspended` (ручной статус по матрице 001.30b, инициатор
  — администратор), запись `audit_log`; ответ — выборка `complaints.py` без адресов; разрешение —
  Admin и выше (security.md §7.1, матрица 001.48, В-39)
- событие `node_suspended_by_provider` — `emit` в транзакции перехода; `emit` ставит одну задачу
  `notify.webhook` (001.52), доставку webhook приложения с идентификатором события выполняет
  001.79: правилом Alertmanager оно не является, ручные статусы алертов не порождают (§17.4);
  перевод по повторным удержаниям (001.30c) этого события не порождает (В-5)

#### Файл: `control-plane/app/jobs/handlers/maintenance.py`

- изменение кода задачи-зависимости 001.37: `retention.purge` вызывает функцию удаления
  `provider_complaints` по сроку (12 месяцев, Н-23)

#### Файл: `control-plane/app/api/auth.py`

- `GET /auth/aup` без аутентификации — текущая версия и ссылка на текст правил, ссылка на
  политику конфиденциальности и режим регистрации `registration_mode` (`open` | `invite` |
  `closed`, ключ `settings` 001.14) для формы регистрации (001.63): в режиме `invite` форма
  показывает поле Redeem-кода (В-31); операция `aup` строки `/auth` таблицы маршрутов
  interfaces.md

#### Файл: `control-plane/app/domain/users.py`

- текущая версия и ссылка на текст правил — из `settings.aup`, политика конфиденциальности — из
  `settings.privacy_policy`, режим регистрации — из `settings.registration_mode`; их отдаёт
  `GET /auth/aup`
- изменение принятого кода (001.14: `aup_version` обязателен, принимается любая строка): регистрация
  с версией, отличной от текущей, — 422 `aup_outdated` (TC-E2E-01)

### Интеграция компонентов

Строки `provider_complaints` хранятся 12 месяцев, как Audit Log (Н-23): функцию удаления по сроку
и её вызов в `retention.purge` (001.37) добавляет эта задача; `app_rw` строк не удаляет. AUP
отображается в web (001.63). Маршрут панели — права и аудит 001.46/001.48; событие — `emit`
001.51/001.52. Ответ провайдеру составляет оператор по руководству (001.71): факт приостановки и
принятые меры; идентификаторы пользователей и объёмы провайдеру не передаются (В-45).

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Регистрация с устаревшей версией правил
   - Входные данные: регистрация с `aup_version`, отличной от `settings.aup`; `GET /auth/aup` при
     `registration_mode = invite`
   - Ожидаемый результат: 422 `aup_outdated`; `GET /auth/aup` отдаёт текущую версию и ссылку на
     текст правил, ссылку на политику конфиденциальности и `registration_mode: invite`
2. **TC-E2E-02:** Обращение провайдера
   - Входные данные: регистрация жалобы
   - Ожидаемый результат: строка `provider_complaints`; нода `suspended`; событие `node_suspended_by_provider` в `events` и одна задача `notify.webhook` (доставка — 001.79); ответ — идентификаторы пользователей и объём по часам, адресов нет
3. **TC-E2E-03:** Срок хранения обращений
   - Входные данные: строки `provider_complaints` с `created_at` старше 12 месяцев и моложе;
     проход `retention.purge`
   - Ожидаемый результат: старая строка удалена функцией владельца, новая осталась; `app_rw` не
     выполнял `DELETE`

### Модульные тесты

1. **TC-UNIT-01:** Выборка по обращению
   - Проверяемая функция: `app/domain/complaints.py` — выборка потребления по ноде за интервал
   - Входные данные: строки `traffic_hourly` ноды внутри интервала и вне его; строки другой ноды
     в том же интервале
   - Ожидаемый результат: только строки интервала этой ноды — идентификатор пользователя, час,
     объём; адресов (источника и назначения) в выборке нет
2. **TC-UNIT-02:** Перевод в `suspended` по обращению
   - Проверяемая функция: обработчик `provider-complaint`
   - Входные данные: сессии `admin` и `operator` (обращение провайдера — Admin и выше, матрица
     001.48)
   - Ожидаемый результат: у `admin` — `suspended`, запись `audit_log`, событие; у `operator` — 403, статус не меняется

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/e2e/test_privacy.py`
- Полный набор: `make test` — существующие тесты проходят.
