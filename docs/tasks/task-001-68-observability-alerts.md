# Задача 001.68: Метрики, Prometheus, Alertmanager, правила §17.4, инструкции разбора

Тип задачи: `[CONFIGURATION]`.

## Связь со сценариями
- UC-07 Отказ и возврат ноды
- UC-04 Учёт трафика и списание с коэффициентом

Требования RTM: R-40, R-47.

## Цель задачи

Экспортировать метрики §9.3 архитектуры из C-01…C-03, настроить Prometheus и Alertmanager с
правилами §17.4 источника и приоритетами алертов вне таблицы (В-42), группировкой, подавлением,
окном обслуживания и инструкцией на каждый алерт; выбрать и подключить внешний сервис мониторинга
вне хоста (В-43): пробы `/healthz` и подписки обоих доменов раз в 1–5 мин, уведомление оператору
и месячная доступность — данные AC-21. Страница состояния этого сервиса и публикация объявлений на
ней и в Telegram-канале — 001.70.

### Интеграция компонентов

Метрики нод — из `node_metrics` через C-01. Источник каждого алерта — ряд `/metrics`; запись ERROR
в журнале служит разбору, а не правилам. Операторские события §4.17, которые строятся по метрикам
(нода недоступна и восстановлена, расхождение сверки, буфер отчётов заполнен), доставляет
Alertmanager этими правилами; идентификатор события в webhook — `groupKey` и `fingerprint`
Alertmanager. «Нода приостановлена провайдером» — однократное событие ручного перехода, правилом
не является и доставляется webhook приложения (001.69, 001.79); перевод в `Suspended` по
повторным удержаниям (001.30c) этого события не порождает — его причина в Audit Log и в алерте
(В-5). Окно обслуживания из панели — 001.85 через API Alertmanager (В-50). «Control Plane
недоступен» и «Subscription-эндпоинт недоступен» доставляет оператору внешний сервис мониторинга
(В-43): Prometheus и Alertmanager стоят на том же хосте и при его отказе молчат.

Правила берут ряды задач-экспортёров ровно под их именами (префикс `control_plane_`):

- `control_plane_inbounds_error{node_id}` — 001.27;
- `control_plane_node_held_suspensions_total{node_id}` — 001.30c;
- `control_plane_node_address_cardinality{node_id}` — 001.38;
- `control_plane_subscription_empty_responses_total` — 001.42;
- `control_plane_node_applied_lag_seconds{node_id}` — 001.75;
- `control_plane_report_intervals_expired{node_id,reason}` — 001.37b;
- `control_plane_report_intervals{node_id,le}` — 001.34 (уже отдаётся);
- ряды доставок почты и webhook по статусам — под именами, которые вводят 001.78 и 001.79.
