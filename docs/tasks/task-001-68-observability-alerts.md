## Примечания

Конфигурационная задача.

Найдено при 001.33 (заглушки), решить здесь:

- длительность каждого принятого интервала отчёта (`period_end − period_start`, 001.34 пишет
  метрикой по ноде): штатный интервал 60 с — обязанность агента (§5.9/Н-17), которую Control
  Plane наблюдает, а не предполагает: алерт на систематическое превышение (нода, отчитывающаяся
  реже штатного, растягивает границу перерасхода Н-17 пропорционально);
- OOM-kill контейнеров с потолком памяти (`api` 1g, `nginx` 256m — 001.33): до политики
  перезапуска 001.66 контейнер после OOM остаётся остановленным — алерт на событие OOM и на
  остановленный контейнер стенда;
- алерты приёма отчётов (001.34): каждое удержание `held_anomaly` (порог §5.9, потолок
  открытых интервалов ноды `REPORT_MAX_OPEN_INTERVALS` 8, смены эпохи сверх
  `REPORT_MAX_EPOCHS_PER_DAY` 48 за скользящие сутки) — нода плодит разрывы или интервалы;
  переводы нод в `suspended` по повторным удержаниям (001.35); принудительные закрытия
  интервалов по сроку и по возрасту; признак рычага зоны парка — рост `rt` при неизменном `urt`
  у остальных нод (задержки очереди в error.log не пишутся);
- сток и срок хранения журналов nginx: `json-file` 10 МиБ × 3 на стенде вымывается за ≈150 000
  строк (анонимный публичный server пишет их дешевле всего), отказы пределов пишутся только в
  access.log статусом (`limit_req_log_level notice` при `error_log … warn`); адреса подписчиков
  (`$remote_addr` строк `/s/` не пишутся, остальные пишутся) — срок хранения по §16 — здесь.
