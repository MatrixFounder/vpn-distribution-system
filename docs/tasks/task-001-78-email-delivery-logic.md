# Задача 001.78: Доставка почты: SMTP-реле, шаблоны на двух языках, отказы, показатель доставки

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-15 Восстановление пароля
- UC-02 Регистрация и активация подписки Redeem-кодом

Требования RTM: R-39, R-41.

<!-- contract:goal -->

## Цель задачи

Реализовать `EmailSender` через SMTP-реле с TLS (ОВ-13), шаблоны 12 событий и служебных писем на
RU/EN, запись `email_deliveries`, обработку отказов с пометкой адреса, показатель доли доставленных
писем подтверждения в `/metrics`.

- шаблоны на двух языках

### Интеграция компонентов

Домен писем и SPF/DKIM/DMARC — 001.66.

Передано из 001.14 (обработчик задач `send_email` очереди `background`): полезная нагрузка
`{kind: verify | reset | reset_unknown, to, lang, token?, user_id?}`, ключ идемпотентности
`email:<id токена>` либо `email:unknown:<uuid>`. Обработчик обязан: (1) `reset_unknown` завершать
без письма — это задача-пустышка, уравнивающая путь кода для неизвестного адреса (UC-15 A1);
(2) не отправлять `verify`/`reset`, чей токен уже просрочен или использован (`email_tokens` по
SHA-256 токена: `expires_at`, `used_at`) — задачи, накопившиеся до выпуска обработчика, не
должны разослать мёртвые ссылки; (3) сырой токен из полезной нагрузки нигде не журналировать.
