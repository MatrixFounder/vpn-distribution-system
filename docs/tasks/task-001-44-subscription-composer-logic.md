# Задача 001.44: Динамический состав серверов: фильтры, статусы, страны, `users_seq`

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-03 Получение подписки клиентом
- UC-07 Отказ и возврат ноды
- UC-06 Продление и смена тарифа

Требования RTM: R-16, R-30.

<!-- contract:goal -->

## Цель задачи

Реализовать `compose` по фильтру R-16: состояние подписки, тариф, группы доступа, протоколы, статус
ноды по матрице §4.6, исправность inbound, доступность по стране, подтверждённый `users_seq` ноды.

- исправность inbound: inbound с ошибкой цели (`error_state` пишет `record_target_check` по результату проверки цели REALITY агентом, 001.27) в выдачу не попадает, остальные inbound ноды выдаются; нода с такой ошибкой — `Degraded` и по §4.6 остаётся в выдаче (решение заказчика 2026-10-25, В-12)
- доступность по стране: нода исключается только при строке `node_country_availability` с `available = false` для страны запроса; строки нет — нода доступна
- подтверждённый состав: строка `node_user_state` пары (пользователь, нода) в состоянии `active` и `nodes.applied_users_seq >= node_user_state.updated_seq`; строки нет — нода не выдаётся

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Offline исключается
   - Входные данные: нода → `offline`
   - Ожидаемый результат: следующий ответ без ноды; после `active` — с нодой (AC-41)
2. **TC-E2E-02:** Неподтверждённый состав
   - Входные данные: нода `active`, `applied_users_seq` ноды меньше `updated_seq` строки пользователя; неподтверждённое изменение строки другого пользователя той же ноды
   - Ожидаемый результат: нода не выдаётся до подтверждения (UC-01 шаг 11); изменение другого пользователя выдачу не скрывает
3. **TC-E2E-03:** Доступность по стране
   - Входные данные: строка `node_country_availability` с `available = false` для страны запроса; страна без строки
   - Ожидаемый результат: в первом случае нода исключена; во втором выдаётся
4. **TC-E2E-04:** Выключенный inbound
   - Входные данные: нода из трёх inbound, один выключен; формат `base64`
   - Ожидаемый результат: две записи на ноду (AC-28)
5. **TC-E2E-05:** Inbound с ошибкой цели
   - Входные данные: нода `degraded` из трёх включённых inbound, у одного заполнен `error_state`; формат `base64`
   - Ожидаемый результат: две записи на ноду; записи inbound с `error_state` нет; после очистки `error_state` — три записи
6. **TC-E2E-06:** Смена тарифа меняет состав
   - Входные данные: тариф A с группой доступа ноды X и профилем `vless_raw_vision`, тариф B с
     группой ноды Y и профилем `trojan_reality`; подписка тарифа A; смена тарифа на B
     (`SubscriptionService.change_plan`, UC-06 A2); агент нод подтверждает состав
   - Ожидаемый результат: до смены в ответе только записи ноды X профиля `vless_raw_vision`; после
     подтверждения состава (`applied_users_seq`) в пределах Н-13 (максимум 60 с) — только записи
     ноды Y профиля `trojan_reality` (AC-42)

### Модульные тесты
