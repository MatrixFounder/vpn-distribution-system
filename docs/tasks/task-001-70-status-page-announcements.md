## Цель задачи

Включить страницу состояния внешнего сервиса мониторинга, выбранного 001.68 (ОВ-A2; решение
заказчика 2026-10-25, В-43), с инцидентами по пробам `/healthz` и подписки обоих доменов и
публиковать объявления на ней и в Telegram-канале. Выбор поставщика, пробы раз в 1–5 мин,
уведомление оператору и месячная доступность — данные AC-21 — 001.68 (R-47); здесь их настройка не
повторяется. Завести независимый канал объявлений — Telegram-канал (ОВ-15; решение заказчика
2026-10-25, В-44), запрашивать согласие на канал при регистрации и описать процедуру смены домена
подписки: объявление в Telegram-канале, на странице состояния и в кабинете, подписанное ключом,
отпечаток которого заранее показан пользователю.

## Описание изменений

### Новые файлы

- `deploy/status/README.md` — страница состояния внешнего сервиса, который выбирает и настраивает
  001.68 (`deploy/prometheus/external-probes.md`): автоматическая публикация инцидентов по пробам
  и ручные объявления; Telegram-канал; шаблоны объявлений; ключ подписи объявлений — закрытый ключ
  вне хоста, у оператора и второго держателя §17.12, его отпечаток опубликован заранее в
  кабинете, в описании Telegram-канала и на странице состояния; инструмент подписи и проверки;
  процедура смены домена: развёртывание нового домена (`deploy/README.md`; шаги развёртывания —
  001.66, DNS — 001.66e, сертификат — 001.66b), подписанное объявление во всех трёх местах,
  проверка подписи пользователем по отпечатку
- `control-plane/app/api/announcement.py` — `GET /api/v1/announcement` (сессия кабинета):
  отпечаток ключа подписи объявлений и действующее объявление о смене домена с подписью из
  ключа `settings.announcement` (`{key_fingerprint, text, signature}`); сервер текст не
  подписывает и закрытого ключа не хранит

Согласие на канал объявлений запрашивается при регистрации (`/auth/register`) и меняется в профиле
(001.16). Флажок добавляется на экран регистрации 001.63 — зависимость от 001.63. Пробы `/healthz`
и подписки обоих доменов, уведомление оператору и месячная доступность для AC-21 — 001.68

из Alertmanager не строится: Alertmanager стоит на том же хосте (В-43). Замена домена подписки
(В-27): шаги развёртывания — 001.66, DNS — 001.66e, сертификат — 001.66b.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Инцидент публикуется
   - Входные данные: на развёртывании с публичными доменами проба подписки одного домена не
     проходит
   - Ожидаемый результат: инцидент на странице состояния внешнего сервиса
2. **TC-E2E-02:** Согласие при регистрации
   - Входные данные: регистрация с `announce_consent: true`; регистрация без поля
   - Ожидаемый результат: `users.announce_consent` — `true` и `false` соответственно
3. **TC-E2E-03:** Объявление в кабинете
   - Входные данные: `announce` с подписью, верной по отпечатку; затем с неверной; запрос
     `GET /api/v1/announcement` с сессией и без неё
   - Ожидаемый результат: верная подпись записана, кабинет получает отпечаток, текст и подпись;
     неверная — отказ подкоманды, значение не меняется; без сессии — 401

### Модульные тесты

1. **TC-UNIT-01:** Проверка подписи объявления
   - Проверяемая функция: проверка подписи подкоманды `announce`
   - Входные данные: текст с подписью ключа отпечатка; тот же текст с изменённым символом;
     подпись другого ключа
   - Ожидаемый результат: принимается только первая пара

### Регрессионные тесты

- Полный набор: `make check` — существующие тесты проходят.
