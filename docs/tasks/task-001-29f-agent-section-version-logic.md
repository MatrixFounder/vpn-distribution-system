# Задача 001.29f: Версия раздела `agent` из колонки ноды

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-01 Ввод ноды в эксплуатацию
- UC-11 Обновление парка нод

Требования RTM: R-04.

<!-- contract:goal -->

## Цель задачи

Выдавать версию раздела `agent` ответа состояния (контракт 001.26: поле `agent.version`, курсор
запроса `agent_section_version`) из колонки ноды вместо заглушки `STUB_AGENT_VERSION` и перевести
`max_conn_per_ip` раздела на колонку `nodes.max_conn_per_ip`. Поток конфигурации — 001.29c;
остальные поля раздела переходят на источник у своих владельцев: `new_conn_rate_per_ip` — 001.27
(В-10), `multiplier_milli` — 001.36, `disconnect_strategy` — 001.40.

## Описание изменений

### Изменения в существующих файлах

#### Файл: `control-plane/app/domain/composition.py`

- раздел `agent`: `version` — колонка ноды (см. миграцию), `max_conn_per_ip` — колонка
  `nodes.max_conn_per_ip`; `new_conn_rate_per_ip` (001.27), `multiplier_milli` (001.36),
  `disconnect_strategy` (001.40) остаются на заглушке `STUB_AGENT` до своих владельцев
- курсор `agent_section_version` запроса выше колонки — 409 `cursor_ahead`, ниже — раздел
  выдаётся (правило заглушки 001.28 на значении колонки)

#### Миграция `control-plane/migrations/NNN_*.sql`

- колонка версии раздела `agent` у `nodes` (`agent_section_version int NOT NULL`): в
  `data-model.md` §4.2.3 её нет — вносится этой задачей. Начальное значение существующих строк
  больше `STUB_AGENT_VERSION` (1), если `max_conn_per_ip` ноды отличается от значения заглушки:
  нода, применившая версию 1, иначе осталась бы на значениях заглушки

#### Файлы: `docs/architectures/data-model.md`, `contracts/agent_v1/README.md`

- колонка версии раздела `agent` у `nodes`; строка `version` раздела `agent` в README контракта
  переадресуется с 001.29 на эту задачу

### Интеграция компонентов

Задача, переводящая поле раздела `agent` на источник или меняющая его значение (001.27, 001.36,
001.40, 001.87), увеличивает версию раздела у затронутых нод.
