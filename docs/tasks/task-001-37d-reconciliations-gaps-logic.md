# Задача 001.37d: Три сверки §5.9 и разрывы

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-04 Учёт трафика и списание с коэффициентом
- UC-10 Восстановление Control Plane из резервной копии

Требования RTM: R-21.

## Цель задачи

Реализовать три сверки §5.9 источника — арифметическую, межисточниковую и непрерывность — с
записью `reconciliation_runs` и разрывов `traffic_gaps` и событием `reconciliation_mismatch` при
расхождении. Часть выделена из 001.37 по правилу 4 «Цикла задачи» (решение заказчика 2026-10-25,
В-47).

### Изменения в существующих файлах

#### Файл: `control-plane/app/accounting/reconcile.py`

- `arithmetic(conn, day)`, `cross_source(conn, node_id, day, tolerance_pct)` (ОВ-24), `continuity(conn, node_id)` — подключение обработчика первым аргументом; запись `reconciliation_runs` (`ReconciliationRun.scope` — неизменяемое отображение), `traffic_gaps`, алерты
- арифметическая сверка — обе стороны по суткам `period_start` отчёта: expected — Σ `traffic_lines.billable_bytes` за сутки `period_start` по строкам, у которых есть период подписки (правило отнесения к периоду — 001.77c, решение заказчика 2026-10-25, В-1; строки без периода исключаются); actual — Σ `balance_entries.delta_billable_bytes` источников `report` и `late_report`, чей `ref_key` ссылается на отчёты с `period_start` в тех же сутках; `adjustment` и `bonus` не учитываются; сверка суток D повторяется до D+3 (окно приёма 72 ч)
- межисточниковая сверка: expected = (rx + tx) / 2 по `node_interface_hourly` ноды за сутки (байт пользователя проходит порт ноды дважды); actual = Σ(`raw_uplink_bytes` + `raw_downlink_bytes`) `traffic_hourly` ноды за сутки; алерт, если (expected − actual) / expected вне коридора `settings.cross_source_tolerance_pct`; удержанная часть входит в `traffic_hourly` только долей `charged`, `capped` — нулём (решение заказчика 2026-10-25, В-2, 001.77b): сверка сравнивает интерфейс с объёмом, принятым к списанию, и недостача по `capped` части видна как расхождение — разрыв по ней пишет сверка непрерывности
- расхождение сверх Н-18 (арифметическая), сверх коридора ОВ-24 (межисточниковая) и новый разрыв (непрерывность) → `emit(conn, reconciliation_mismatch, node_id=…, payload={kind, day, delta_pct})` в транзакции записи прогона; запись журнала ERROR для 001.68 — как прежде
- разрыв на недостающие части интервала записывает сверка непрерывности этой задачи: приём 001.34 и задача закрытия интервалов молчащих нод 001.37b только закрывают интервал и пишут `close_reason`

#### Файл: `control-plane/app/jobs/handlers/__init__.py`

- типы `reconcile.daily`, `reconcile.continuity`; обработчик `reconcile.continuity` в одном проходе сначала вызывает функцию закрытия истёкших интервалов `close_expired_intervals(conn, at)` 001.37b, затем сверку: порядок держит обработчик, а не расписание

#### Файл: `control-plane/app/jobs/scheduler.py`

- расписание: сверка непрерывности — каждые 15 минут (ревью WI-35, группа ACC-F-20); арифметическая и межисточниковая сверки 00:30 UTC (смещение `Periodic.offset` — 001.37)

### Интеграция компонентов

Событие `reconciliation_mismatch` — через `emit` 001.51 (зависимость от 001.51 — в PLAN).
Функция закрытия истёкших интервалов — 001.37b. Идемпотентность записи разрыва держит первичный

«Расхождение сверки трафика свыше Н-18» (001.68).

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Арифметическая сверка
   - Входные данные: отчёты за сутки и балансы, включая поздний отчёт этих суток, принятый после полуночи
   - Ожидаемый результат: расхождение 0 %; при подмене баланса > 0,5 % — алерт (Н-18) и событие `reconciliation_mismatch`
2. **TC-E2E-02:** Непрерывность
   - Входные данные: пропуск `report_seq`
   - Ожидаемый результат: `traffic_gaps` строка; алерт; событие `reconciliation_mismatch`; повторный проход разрыв не удваивает
3. **TC-E2E-03:** Межисточниковая сверка
   - Входные данные: сутки ноды, где rx + tx интерфейса равно удвоенной сумме `raw`; затем отклонение больше 15 %
   - Ожидаемый результат: расхождение 0 %; затем алерт и событие `reconciliation_mismatch`
4. **TC-E2E-04:** Закрытие перед сверкой в одном проходе
   - Входные данные: интервал из трёх частей, часть 1 принята в T; нода молчит; задача `report_intervals.close_expired` не выполнялась; один проход `reconcile.continuity` в T + 25 ч 10 мин
   - Ожидаемый результат: в этом проходе интервал закрыт (`close_reason = deadline`, `closed_at` = T + 25 ч) и записан разрыв на части 2 и 3; повторный проход разрыв не удваивает

### Регрессионные тесты

- Полный набор: `make test` — существующие тесты проходят.

## Примечания

Ограничения и допущения — `docs/idea.md` §9; архитектура — `docs/ARCHITECTURE.md`.

Найдено при 001.33 (заглушки), решить здесь:

- сверка непрерывности обязана видеть буфер, остановленный отказом `node_mismatch` или
  `rejected_time` (номера `report_seq` перестают расти), и фиксировать разрыв, а не тишину;
- три новых источника разрывов (контракт 001.33, README `contracts/agent_v1/`): интервал,
  закрытый без всех объявленных частей — по сроку `REPORT_PARTS_DEADLINE` (25 часов: буфер
  Н-8 плюс час) или частью следующего интервала ноды (001.34 закрывает интервал и пишет
  `close_reason`; разрыв на недостающие части записывает сверка непрерывности этой задачи;
  поздняя часть получает `interval_closed` и в учёт не входит — двойного учёта нет), и
  смена `counter_epoch` (для Control Plane перезапуск Xray и перерыв агента неразличимы —
  правило одно): оценка объёма разрыва — полоса ноды × длительность паузы между `period_end`
  последней принятой части прежней эпохи и `period_start` первой части новой, а не
  «неизвестная эпоха — оценка не ограничена»; смен эпохи у ноды — не больше
  `REPORT_MAX_EPOCHS_PER_DAY` (48) в сутки (001.34 удерживает сверх).

Найдено при 001.34 (приём), решить здесь:

- интервал `capped` (часть сверх потолка открытых интервалов, без списания) — разрыв на весь
  объём его частей, а не только на недостающие;
- источники разрывов: интервал, закрытый без всех частей (`superseded`, `deadline`, `age`),
  отказанные части (`traffic_reports.status` `rejected_time`, `interval_closed` — номер
  пропущен), смена эпохи (между концом последнего интервала прежней и началом первого новой),
  интервал, первая часть которого отказана (второй источник пуст — разрыв второго источника,
  а не ноль).

Найдено при создании 001.87 (вывод ноды), решить здесь:
