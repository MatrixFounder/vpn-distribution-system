# Задача 001.81: Node Agent: исполнение команд и `update_agent` с откатом

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-11 Обновление парка нод
- UC-12 Компрометация ноды

Требования RTM: R-04, R-07, R-20, R-44.

<!-- contract:goal -->

## Цель задачи

Реализовать исполнение команд: дедупликация по `commands[].id` (в idea — `command_id`) в Store,
`expires_at` → результат `expired`, четыре типа команд, `update_agent` для агента и для Xray с
загрузкой, проверкой контрольной суммы, заменой бинарного файла, перезапуском через systemd и
откатом при неуспехе; ротацию identity по `rotate_credentials` (В-16), ограниченный сбор
`collect_diagnostics` (В-18) и локальную подкоманду вывода ноды `node-agent decommission` (В-21).

## Описание изменений

### Новые файлы

- `node-agent/internal/sync/commands_test.go` — просроченная команда; повтор; неуспешное
  обновление → откат и `failed`; ротация identity; предел и маска `output` диагностики
- `node-agent/internal/app/decommission_test.go` — вывод ноды при доступном и недоступном Control
  Plane: что затирается после слива и что остаётся при отказе
- `node-agent/internal/app/decommission.go` — `func Decommission(ctx, cfg) error`: вывод ноды из
  эксплуатации на стороне агента, запуск администратором по SSH (решение заказчика 2026-10-25,
  В-21): остановка службы `node-agent`, финальное чтение счётчиков и слив буфера до пустого
  (001.56), остановка Xray. После успешного слива затираются: файлы identity обоих поколений
  (`cert.pem`, `key.pem`, `ca.pem`, `token`); конфигурация Xray `/etc/xray/config.json` с
  приватными ключами REALITY inbound (001.80); база Store в `/var/lib/node-agent` — локальный
  состав с credentials пользователей (001.80), состояние агента и пустой буфер (001.56). Слив не
  завершён (Control Plane недоступен) — код выхода ≠ 0, ничего из перечисленного не затирается,
  подкоманду можно повторить. Канал команд не используется: у `disabled` и `suspended` он закрыт,
  а §5.2 фиксирует четыре типа команд

### Изменения в существующих файлах

#### Файл: `node-agent/internal/sync/commands.go`

- реализация четырёх команд; результат через `CommandResult`; порядок исполнения — по `issued_at`
- `update_agent` (нагрузка `{component: agent | xray, version, url, sha256}`, 001.31): для агента —
  загрузка, проверка суммы, замена бинарного файла, перезапуск через systemd, откат при неуспехе;
  для Xray — финальное чтение счётчиков (001.56), загрузка и проверка суммы, замена бинарного
  файла, перезапуск с возвратом состава (001.80), новая эпоха, откат при неуспехе
- `restart_xray` — путём 001.80: финальное чтение, перезапуск, новая эпоха, возврат состава
- `rotate_credentials` (нагрузка `{}`) — новый ключ EC P-256, CSR, операция
  `POST /agent/v1/identity/rotate` по mTLS с токеном действующей identity: тело `{csr_pem}`, ответ
  200 `{client_cert_pem, identity_token, generation}` (контракт и фикстура `identity-rotate.json` —
  001.31); новое поколение identity хранится рядом с прежним, переключение — после успеха, прежнее
  хранится до конца окна перекрытия Н-28 — 7 суток от ротации; смена `state_generation` продлевает
  открытое окно до момента смены плюс 7 суток (`extend_overlap_windows`, 001.31; прежнее поколение
  предъявляет повторное подтверждение, 001.54). Команду выдаёт планировщик Control Plane
  автоматически, когда до конца срока листа остаётся не больше 30 дней; агент сам ротацию не
  начинает (решение заказчика 2026-10-25, В-16)
- `collect_diagnostics` (нагрузка `{}`) — ограниченный набор в поле `output` результата команды,
  не больше 65 536 байт в UTF-8 (64 КиБ; длиннее Control Plane отвергает 422; поле, предел и
  фикстура `command-result-diagnostics.json` — изменение контракта agent_v1 в 001.31; `output`
  принимается только в результате `collect_diagnostics`): версии агента и Xray, состояние служб
  `xray` и `node-agent` (systemd), хвост журнала агента. Адресов пользователей в `output` нет: все
  адреса IPv4 и IPv6 в строках журнала заменяются маской. При превышении предела укорачивается
  хвост журнала, новые строки сохраняются (решение заказчика 2026-10-25, В-18)

#### Файл: `node-agent/cmd/node-agent/main.go`

- подкоманда `decommission` — вызов `app.Decommission`; запуск без подкоманды — прежний цикл
  `app.Run`

### Интеграция компонентов

Полезные нагрузки `update_agent` и `rotate_credentials`, операция Node API подачи CSR при ротации
(`POST /agent/v1/identity/rotate`), поле `output` результата команды и их фикстуры — 001.31
(изменение контракта agent_v1 — в 001.31); выдача, срок и статусы команд — 001.76; эта задача
зависит от обеих. Финальное чтение и слив буфера — 001.56, возврат состава после старта Xray —
001.80. Сторона Control Plane вывода ноды (отметка вывода, отзыв identity общим шагом отзыва, аудит)
— 001.87; запись периода недоучёта при выводе — по ответу на вопрос «решить здесь» 001.87;
инструкция оператора — 001.71.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Команда просрочена
   - Входные данные: доставленная команда, чей `expires_at` истёк до исполнения
   - Ожидаемый результат: результат `expired`; не исполнена (UC-11 A3)
2. **TC-E2E-02:** Неуспешное обновление
   - Входные данные: неверная контрольная сумма
   - Ожидаемый результат: откат; результат `failed`; агент работает на прежней версии
3. **TC-E2E-03:** Неуспешное обновление Xray
   - Входные данные: `update_agent` с `component: xray` и неверной контрольной суммой архива
   - Ожидаемый результат: откат; результат `failed`; работает прежняя версия Xray, состав в
     inbound
4. **TC-E2E-04:** Ротация identity
   - Входные данные: команда `rotate_credentials`; тестовый Control Plane принимает CSR
   - Ожидаемый результат: новое поколение записано (0600) рядом с прежним; следующие запросы идут
     с новым; прежнее сохранено до конца окна; результат `applied`
5. **TC-E2E-05:** Сбор диагностики
   - Входные данные: команда `collect_diagnostics`; журнал агента со строками, содержащими адреса
     IPv4 и IPv6, объёмом больше 64 КиБ
   - Ожидаемый результат: `output` не больше 64 КиБ; содержит версии и состояние служб; адресов
     IPv4 и IPv6 нет; сохранены последние строки журнала
6. **TC-E2E-06:** Вывод ноды
   - Входные данные: `node-agent decommission`; в буфере неотправленные интервалы; тестовый
     Control Plane доступен
   - Ожидаемый результат: финальный интервал принят; файлы identity обоих поколений,
     `/etc/xray/config.json` и база Store (локальный состав с credentials, состояние, буфер)
     удалены
7. **TC-E2E-07:** Вывод ноды без связи
   - Входные данные: `node-agent decommission`; Control Plane недоступен
   - Ожидаемый результат: код выхода ≠ 0; буфер, файлы identity, `/etc/xray/config.json` и база
     Store на месте

## Критерии приёмки

- [ ] Неуспешное обновление агента или Xray оставляет ноду работоспособной
- [ ] Повтор команды не исполняется
- [ ] Ротация не прерывает работу ноды: прежнее поколение действует до конца окна (Н-28, В-16)
- [ ] `output` диагностики не больше 64 КиБ и без адресов пользователей (В-18)
- [ ] `node-agent decommission` после слива буфера затирает identity, конфигурацию Xray с
  ключами REALITY и базу Store с credentials пользователей; без слива не затирает ничего (В-21)
