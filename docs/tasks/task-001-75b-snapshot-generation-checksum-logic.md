## Цель задачи

Реализовать полный снапшот (все строки кроме `removed`), обработку несовпадения `state_generation`
(409 → снапшот) и контрольную сумму состава `users.checksum`. Подтверждение курсоров — 001.75;
удержание long-poll — 001.75c.

- дополнить: снапшот; `generation`

#### Файл: `control-plane/app/domain/composition.py`

- `state_for(full=1)`
- `generation` запроса и ответа — `settings.state_generation` (поколение потока состава, смена при восстановлении — 001.67), а не поколение identity: 409 `generation_mismatch` с `details.generation` = текущее поколение; снапшот с чужим поколением тоже получает 409, и агент повторяет `full=1` с `details.generation`. Поколение identity (`node_identities.generation`, растёт с каждым обменом токена) с ним не сверяется и из него не выводится
- `users.checksum` — SHA-256 канонической записи набора строк состава, отсортированного по `user_id` (поля `user_id`, `state`, `credentials.version`, `quota_grant_bytes`, `quota_issued_seq`, `blocked_ips`); каноническая запись — та же, что у `config.checksum` (README, «Контрольная сумма конфигурации»: ключи отсортированы, разделители без пробелов, UTF-8). `quota_grant_bytes` пользователя без лимита (Unlimited) — `null` (решение заказчика В-6, 001.36): в канонической записи ключ присутствует со значением JSON-литерала `null`; ключ не опускается и не заменяется на `0`. `quota_issued_seq` — номер выдачи гранта в строке состава (001.36): агент применяет грант по номеру, и две выдачи одного объёма без номера в записи дали бы одну сумму. Поле в строку состава вводит 001.36: если она принята раньше этой задачи, поле входит в запись здесь; иначе 001.36 добавляет его в каноническую запись, правило README и TC-UNIT-01 этой задачи (запись об этом — в 001.36)

#### Файл: `contracts/agent_v1/README.md`, фикстуры `contracts/agent_v1/state-*.json`

- Изменение контракта agent_v1: поле `users.checksum` в ответе состояния, правило его канонической записи (включая `quota_grant_bytes: null` литералом `null`) — в README рядом с «Контрольная сумма конфигурации»; смысл `generation` — `state_generation`: строка README о `state-generation-mismatch.json` («чужое поколение identity»), раздел о 409, `summary` и `message` фикстуры `state-generation-mismatch.json`

#### Файлы: `control-plane/app/agent_api/state.py`, `control-plane/app/domain/composition.py`, `control-plane/tests/e2e/test_agent_api.py`

### Интеграция компонентов

ответов 200 и из `details.generation` ответа 409. Ответ снапшота с `users.full = true` снимает
`resync_required` по правилу 001.75.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Откат базы
   - Входные данные: `generation` в запросе ≠ `settings.state_generation`
   - Ожидаемый результат: 409 `generation_mismatch` с `details.generation`; запрос `full=1` с прежним поколением — тоже 409; запрос `full=1` с `details.generation` возвращает снапшот (UC-10)

### Модульные тесты

1. **TC-UNIT-01:** Контрольная сумма
   - Проверяемая функция: `app/domain/composition.py::checksum`
   - Входные данные: одинаковые наборы строк в разном порядке; набор с другой `credentials.version`; набор с другим `quota_issued_seq` (поле 001.36); строка с `quota_grant_bytes = null` (Unlimited) и та же строка с `quota_grant_bytes = 0` и без ключа `quota_grant_bytes`
   - Ожидаемый результат: равные значения; другое значение в обоих случаях; сумма строки с `null` равна SHA-256 записи с литералом `"quota_grant_bytes":null` и отличается от сумм с `0` и без ключа

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/unit/domain/test_composition.py -k checksum && pytest tests/e2e/test_agent_api.py -k 'snapshot or generation'`
- Полный набор: `make test` — существующие тесты проходят.

Найдено при 001.28 (заглушки), решить здесь:

- снапшот не удерживается и ничего не стоит: `?full=1` отвечает немедленно при любых курсорах,
  а в бою это полное чтение `node_user_state` с расшифровкой credentials выборки. Ограничение
  частоты по identity — 001.72 (этап 12), то есть окно между этапами ничем не закрыто: нужен
  собственный предел на снапшот — выдержка на ноду либо удержание, когда курсоры запроса уже
  совпадают с текущими.


Найдено при 001.33 (роаст раунда 8), решить здесь:

- потолок размера снапшота состава — число, из которого выводится размер tmpfs временных файлов
  ответов прокси (число нод × потолок): сегодня 64 МиБ — восемь ответов по 8 МиБ одного
  сертификата (`agent_conn 8`), не потолок парка, и каталог общий с телами публичного server
  (001.66b); ответ больше `proxy_max_temp_file_size` 8 МиБ прокси читает в темпе клиента —
  потолок снапшота обязан быть ниже (роаст раунда 8).
