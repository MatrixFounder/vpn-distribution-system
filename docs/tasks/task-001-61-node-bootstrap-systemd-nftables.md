Тип задачи: `[CONFIGURATION]`.

- UC-01 Ввод ноды в эксплуатацию

## Цель задачи

Подготовить установку ноды одной командой по `docs/architectures/deployment.md` §10.4: Xray-core
v26.3.27 с проверкой контрольной суммы, `node-agent`, юниты systemd, конфигурация агента с двумя
адресами и якорем доверия (сертификат серверного CA, 001.66d), синхронизация часов, пакет
nftables; сборка bootstrap-команды на стороне Control Plane.

## Описание изменений

### Новые файлы

- `deploy/node/bootstrap.sh` — `bootstrap.sh <enroll_url> <agent_url> <token> <ca>`: установка, юниты, `config.yaml`, первый запуск
  - сертификат серверного CA (`BootstrapToken.ca_pem` — офлайн-CA серверных сертификатов
    агентских портов, 001.66d; security.md §7.1) — якорь доверия: канал
    администратора (панель по HTTPS → его сессия SSH) — единственный аутентифицированный путь до
    первого обмена. Форма передачи — на выбор задачи (base64 PEM аргументом, here-doc); скрипт
    пишет CA в `server-ca.pem` и путь в `config.yaml` до первого запуска агента, без CA агента не
    запускает
  - синхронизация часов (systemd-timesyncd или chrony) включается и проверяется
    (`timedatectl show -p NTPSynchronized`); без синхронизации агент не запускается (§5.9: допуск
    5 с)
  - `config.yaml`: `XrayAPI: 127.0.0.1:10085` — то же значение, что `api.listen` генератора
    конфигурации (001.26); начальный `/etc/xray/config.json` — только раздел API, до первого
    потока конфигурации
  - пакет `nftables` устанавливается и служба включается; набор правил §16.6 агент загружает в
    собственную таблицу `table inet node_agent` (001.86), файла правил задача не поставляет.
    Значения правил — из раздела `agent` ответа состояния, в том числе обязательное поле ноды
    `new_conn_rate_per_ip` (частота новых входящих соединений с одного адреса клиента, 001.27) без
    значения по умолчанию; `bootstrap.sh` их не задаёт (решение заказчика 2026-10-25, В-10)
- `deploy/node/xray.service` — юнит Xray: `-config /etc/xray/config.json`, `Restart=always`
- `deploy/node/node-agent.service` — юнит агента: `After=xray.service`, `Restart=always`, watchdog
- `deploy/node/XRAY_SHA256` — контрольная сумма архива Xray-core v26.3.27 (О-8)

### Изменения в существующих файлах

#### Файл: `control-plane/app/config.py`

- Изменение принятого кода (передано из 001.24: адресов в настройках нет, команду собирает 001.61
  вместе с переменной адреса): адреса enrollment-порта и `/agent/v1` — переменные настроек (`.env`)

#### Файл: `control-plane/app/domain/nodes.py`

- Изменение принятого кода (передано из 001.24: команда bootstrap в ответ выдачи токена не
  включена; модель — 001.24 и 001.25): `BootstrapToken` дополняется полем
  `bootstrap_command` — команда с токеном, обоими адресами и `ca_pem`; панель её показывает
  (001.64); тест — `control-plane/tests/e2e/test_nodes.py` (контракт OpenAPI с новым полем,
  TC-E2E-02)

### Интеграция компонентов

Команду собирает эта задача (поле ответа выдачи токена); ответ выдачи токена — 001.25, `ca_pem` в
нём — сертификат серверного CA (001.66d), показ команды в панели — 001.64. История оболочки —
риск, снимаемый одноразовостью токена.

1. **TC-E2E-01:** Установка в чистом контейнере
