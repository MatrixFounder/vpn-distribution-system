# Задача 001.65: Локализация RU/EN и часовой пояс: сервер, письма, страница подписки, интерфейсы

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-16 Работа в личном кабинете
- UC-15 Восстановление пароля

Требования RTM: R-51, R-52.

<!-- contract:goal -->

## Цель задачи

Реализовать выбор языка (профиль → `Accept-Language` → `en`) на сервере, шаблоны писем и страницы
подписки на двух языках, хранение времени в UTC и отображение в поясе профиля; добавление третьего
языка — только файлами.

<!-- contract:changes -->

## Описание изменений

### Изменения в существующих файлах

#### Файл: `control-plane/app/i18n.py`

- `negotiate(user, accept_language) -> str`; загрузка `locales/{ru,en}.json`; тест полноты ключей

#### Файл: `control-plane/app/notifications/templates/`

- шаблоны 12 событий на двух языках

#### Файл: `control-plane/app/subscription/page.py`

- локализация страницы

#### Файл: `control-plane/app/api/me.py`

- время в ответах — ISO 8601 UTC; пояс профиля возвращается клиенту для отображения

### Интеграция компонентов

Web-пакет `i18n` (001.62) и серверные файлы проверяются одним тестом полноты ключей.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Язык профиля
   - Входные данные: профиль `en`, запрос с `Accept-Language: ru`
   - Ожидаемый результат: письмо и страница на английском (AC-22)
2. **TC-E2E-02:** Третий язык
   - Входные данные: добавлен `de.json` без изменения кода
   - Ожидаемый результат: интерфейс на немецком при профиле `de`

### Модульные тесты

1. **TC-UNIT-01:** Согласование языка
   - Проверяемая функция: `app/i18n.py::negotiate`
   - Входные данные: без профиля, `Accept-Language: de, ru;q=0.8`
   - Ожидаемый результат: `ru`

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/unit/test_i18n.py && cd ../web && npm run test -- packages/i18n`
- Полный набор: `make test` — существующие тесты проходят.
