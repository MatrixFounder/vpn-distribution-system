# Задача 001.65: Серверная локализация: согласование языка, файлы `locales/`, набор языков из файлов

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-16 Работа в личном кабинете
- UC-15 Восстановление пароля

Требования RTM: R-51, R-52.

<!-- contract:goal -->

## Цель задачи

Реализовать выбор языка (профиль → `Accept-Language` → `en`) на сервере для ответов, писем и
страницы подписки и хранение времени в UTC; добавление третьего языка на сервере — только файлом
`locales/`. Web-локализация и отображение времени в поясе профиля — 001.65b (дробление по В-47,
решение заказчика 2026-10-25).

<!-- contract:changes -->

## Описание изменений

### Изменения в существующих файлах

#### Файл: `control-plane/app/i18n.py`

- `negotiate(user, accept_language) -> str`; загрузка `locales/*.json` и выдача строки по ключу и
  языку; тест полноты ключей серверных файлов: у каждого файла `locales/` тот же набор ключей, что
  у `en.json`
- изменение принятого кода (отступление от 001.10): `SUPPORTED_LANGUAGES` — из списка файлов `locales/`, а не константа

#### Файл: `control-plane/app/domain/profile.py` — изменение принятого кода (отступление от 001.15)

- `Language` — из списка файлов `locales/`, а не `Literal["en", "ru"]`: профиль принимает язык, добавленный файлом

#### Файл: `control-plane/app/api/auth.py` — изменение принятого кода (отступление от 001.13, 001.14)

- язык регистрации: `lang` из тела запроса, если передан, иначе `negotiate(None, Accept-Language)`; набор допустимых значений — из списка файлов `locales/`, а не `Literal["en", "ru"]`

#### Файл: `control-plane/app/api/me.py`

- время в ответах — ISO 8601 UTC; пояс профиля возвращается клиенту для отображения (отображение
  в поясе — 001.65b)

### Интеграция компонентов

Язык без профиля выбирается одним правилом на обеих сторонах: первый поддерживаемый язык из списка
предпочтений (`Accept-Language` на сервере, `navigator.languages` в web, 001.62), иначе `en`.

Шаблоны писем: файлы-заглушки — 001.51, тексты на двух языках и выбор шаблона по языку
получателя — 001.78. Язык получателя и набор языков (`SUPPORTED_LANGUAGES`) — эта задача;
загрузчика шаблонов эта задача не вводит: выбор шаблона по типу и языку — `template_for` 001.78.

Страница подписки (`app/subscription/page.py`) создаётся в 001.41 и реализуется в 001.45, включая
её локализацию. Язык страницы — `negotiate` и строки `locales/` этой задачи. Зависимость
развёрнута: 001.45 зависит от 001.65, а не 001.65 от 001.45 (ADM-29; В-47). При прежнем ребре
001.65 → 001.45 серверная почта (001.52, 001.78) ждала бы web-каркас 001.62 и страницу подписки,
а вместе с ребром 001.45 → 001.65 оно дало бы цикл. Проверка «страница подписки на языке профиля»
(прежний шаг TC-E2E-01 этой задачи) — тест 001.45: страница появляется после этой задачи.

Тексты ответов API (`reason` и тексты мастера `/me`, 001.16) берут язык из `negotiate` и строки
из `locales/` этой задачи.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Язык профиля
   - Входные данные: профиль `en`, `POST /auth/reset-request` с `Accept-Language: ru` (UC-15)
   - Ожидаемый результат: задача `send_email` вида `reset` с `lang = en`: язык писем получателя —
     `en`, заголовок запроса язык профиля не меняет (AC-22)
2. **TC-E2E-02:** Третий язык на сервере
   - Входные данные: в `locales/` добавлен `de.json` без изменения кода (фикстура теста);
     `PATCH /me` с языком `de`
   - Ожидаемый результат: `PATCH` профиля с `de` принят; следующий `GET /me` отдаёт `de`
3. **TC-E2E-03:** Язык при регистрации
   - Входные данные: `POST /auth/register` без `lang` с `Accept-Language: de, ru;q=0.8`; второй
     запрос — с `lang = en` в теле и тем же заголовком
   - Ожидаемый результат: язык профиля — `ru`, задача `send_email` вида `verify` с `lang = ru`;
     во втором случае — `en`
4. **TC-E2E-04:** Время в ответах
   - Входные данные: профиль с поясом `Asia/Tokyo`; `GET /me`
   - Ожидаемый результат: все значения времени ответа — ISO 8601 UTC (`Z` или `+00:00`); поле
     пояса — `Asia/Tokyo`

### Модульные тесты

1. **TC-UNIT-01:** Согласование языка
   - Проверяемая функция: `app/i18n.py::negotiate`
   - Входные данные: без профиля, `Accept-Language: de, ru;q=0.8`
   - Ожидаемый результат: `ru`
2. **TC-UNIT-02:** Полнота ключей серверных файлов
   - Проверяемая функция: тест полноты `locales/` (`tests/unit/test_i18n.py`)
   - Входные данные: файлы `locales/`; фикстура с `ru.json` без одного ключа `en.json`
   - Ожидаемый результат: на файлах репозитория тест проходит; на фикстуре — падает с именем
     ключа и файла

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/unit/test_i18n.py tests/e2e/test_auth.py tests/e2e/test_me.py`
- Полный набор: `make test` — существующие тесты проходят.
