# Задача 001.45: Два домена подписки и страница подписки

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-03 Получение подписки клиентом
- UC-16 Работа в личном кабинете

Требования RTM: R-17.

<!-- contract:goal -->

## Цель задачи

Обслуживать оба домена одинаковым содержимым, отделить их от административного API в nginx и
реализовать страницу подписки с инструкциями и кнопками импорта на языке профиля владельца токена
(RU, EN; третий язык — файлом `locales/`, 001.65).

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Домены равнозначны
   - Входные данные: один запрос на два домена
   - Ожидаемый результат: побайтно одинаковые ответы (AC-33)
2. **TC-E2E-02:** Административный API недоступен
   - Входные данные: `GET /api/v1/admin/users` на домене подписки
   - Ожидаемый результат: 404
3. **TC-E2E-03:** Страница на языке профиля
   - Входные данные: `GET /s/{token}` с `Accept: text/html` и `Accept-Language: en`, владелец токена
     с профилем `ru`; тот же запрос после смены языка профиля на `en`; файл `locales/de.json`
     фикстуры теста и профиль `de`
   - Ожидаемый результат: тексты страницы — строки `locales/ru.json`, затем `locales/en.json`;
     заголовок запроса язык не меняет; с профилем `de` — строки `de.json` без изменения кода (AC-22
     в части страницы подписки; проверка перенесена из 001.65)

### Модульные тесты

1. **TC-UNIT-01:** Число доменов подписки
   - Проверяемая функция: `app/config.py::Settings`
   - Входные данные: роль `api`, один домен при `APP_ENV=prod`; два домена при `APP_ENV=prod`; один домен при `APP_ENV=stand`
   - Ожидаемый результат: ошибка конфигурации; настройки прочитаны; настройки прочитаны

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/e2e/test_subscription.py -k "domain or language" && pytest tests/unit/test_config.py` (`-k` действует на все файлы вызова, поэтому `test_config.py` — отдельным вызовом)
- Полный набор: `make test` — существующие тесты проходят.
