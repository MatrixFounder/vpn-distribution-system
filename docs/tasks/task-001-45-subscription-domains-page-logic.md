# Задача 001.45: Два домена подписки и страница подписки

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-03 Получение подписки клиентом
- UC-16 Работа в личном кабинете

Требования RTM: R-17.

<!-- contract:goal -->

## Цель задачи

Обслуживать оба домена одинаковым содержимым, отделить их от административного API в nginx и
реализовать страницу подписки с инструкциями и кнопками импорта на RU/EN.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `control-plane/tests/e2e/test_subscription.py` — одинаковый ответ на двух доменах; `/api/v1` на домене подписки → 404

### Изменения в существующих файлах

#### Файл: `deploy/nginx/nginx.conf`

- `server` для двух доменов подписки только с `location /s/`; административный API на этих доменах — 404

#### Файл: `control-plane/app/subscription/page.py`

- шаблон: платформа по `User-Agent`, ссылки на клиенты, кнопки импорта (deep-link), QR, лимит и срок, объявление; локализация (001.65)

### Интеграция компонентов

Оба домена показываются в кабинете и в письме об активации (001.16, 001.52).

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Домены равнозначны
   - Входные данные: один запрос на два домена
   - Ожидаемый результат: побайтно одинаковые ответы (AC-33)
2. **TC-E2E-02:** Административный API недоступен
   - Входные данные: `GET /api/v1/admin/users` на домене подписки
   - Ожидаемый результат: 404

### Модульные тесты

- Не требуются: задача не содержит логики сверх заглушек или конфигурации.

### Регрессионные тесты

- Команда: `cd control-plane && pytest tests/e2e/test_subscription.py -k domain`
- Полный набор: `make test` — существующие тесты проходят.
