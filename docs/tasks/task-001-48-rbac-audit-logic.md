# Задача 001.48: RBAC: матрица и политики §5.11; Audit Log append-only

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-09 Управление тарифами, группами и кодами
- UC-13 Поддержка пользователя

Требования RTM: R-35, R-37.

<!-- contract:goal -->

## Цель задачи

Реализовать матрицу «роль × операция» (ОВ-26 — распределение спорных операций), политики просмотра
subscription URL, impersonation только для чтения, второе подтверждение сверх порога (ОВ-17), и
запись Audit Log с составом §4.16 источника.

<!-- contract:changes -->

## Описание изменений

### Новые файлы

- `control-plane/tests/e2e/test_admin_auth.py` — каждое действие панели попадает в журнал с актором и ролью (AC-15); `UPDATE audit_log` от `app_rw` → ошибка (AC-39)

### Изменения в существующих файлах

#### Файл: `control-plane/app/security/rbac.py`

- матрица для четырёх ролей; разрешения `users.view_subscription_url`, `users.impersonate`, `codes.export`, `audit.read`, `nodes.revoke_identity`, `nodes.update_agent`, `backup.restore`…

#### Файл: `control-plane/app/security/audit.py`

- запись всех полей §4.16 включая `impersonated_user_id`, `user_agent`, `result`; `old_value`/`new_value` без PII (маскирование адресов почты); чтение `/admin/audit` регистрируется

#### Файл: `control-plane/app/api/admin/users.py`

- `POST /admin/users/{id}/impersonate` — только чтение, начало и завершение в журнале, уведомление пользователя; операции сверх порога `settings.second_approval_threshold` создают запрос подтверждения второй учётной записью

### Интеграция компонентов

Триггер неизменяемости создан в 001.09; здесь — проверка и запись.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Просмотр URL регистрируется
   - Входные данные: Support открывает subscription URL
   - Ожидаемый результат: строка `audit_log` с действием `users.view_subscription_url` (UC-13)
2. **TC-E2E-02:** Журнал неизменяем
   - Входные данные: `UPDATE audit_log` под `app_rw`
   - Ожидаемый результат: ошибка триггера (AC-39)
3. **TC-E2E-03:** Второе подтверждение
   - Входные данные: начисление сверх порога
   - Ожидаемый результат: операция ожидает подтверждения другой учётной записью

### Модульные тесты

1. **TC-UNIT-01:** Маскирование PII
   - Проверяемая функция: `app/security/audit.py::mask`
   - Входные данные: словарь с `email`
   - Ожидаемый результат: адрес заменён на `user_id`
