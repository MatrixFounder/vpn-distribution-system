# Задача 001.86: Node Agent: nftables — лимит соединений с адреса, egress-фильтры, conntrack

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-08 Ограничение числа адресов и перепродажа доступа

Требования RTM: R-28, R-29.

<!-- contract:goal -->

## Цель задачи

Реализовать применение набора nftables (порты 25/587, частные сети, метаданные, частота новых
входящих соединений с одного адреса клиента, лимит одновременных соединений с адреса Н-29) с
параметрами из раздела `agent` ответа состояния и локальный сбор счётчиков conntrack по адресам
для признаков перепродажи. Правило частоты (R-28, AC-40, §16.6) ограничивает новые входящие
соединения с одного адреса клиента на порты inbound, а не исходящие соединения Xray; значение —
обязательная настройка ноды в соединениях в секунду, значения по умолчанию нет (решение заказчика
2026-10-25, В-10).

## Описание изменений

### Изменения в существующих файлах

#### Файл: `node-agent/internal/guard/guard_test.go`

- дополнить (файл создаёт 001.58): набор содержит пять правил §16.6

#### Файл: `node-agent/internal/guard/nftables.go`

- `Render`, `Load`, проверка `nft list ruleset`; набор — в собственной таблице
  `table inet node_agent`; при смене раздела `agent` набор перезагружается без перезапуска Xray
- частота новых входящих соединений: на портах inbound правило `ct state new` с динамическим
  множеством (meter) по адресу источника IPv4 и IPv6 и `limit rate over M/second` → `drop`; M —
  поле `new_conn_rate_per_ip` раздела `agent` (соединений в секунду). Агент значения не
  подставляет: поле обязательное, раздел без него не применяется (ошибка разбора, 001.55), набор
  остаётся прежним

#### Файл: `node-agent/internal/guard/conntrack.go`

- `Stats()` — локальный сбор счётчиков по адресам; в Control Plane не отправляется: поле тела
  метрик `conn_stats[]` и отправку вводит 001.39 (тело метрик закрыто `extra="forbid"`, до приёма
  поля агент его не шлёт)

### Интеграция компонентов

Значения лимитов — раздел `agent` ответа состояния: поля `max_conn_per_ip` и
`new_conn_rate_per_ip` вводит в раздел 001.26, значения — из одноимённых колонок `nodes` (001.27);
`new_conn_rate_per_ip` — обязательное поле записи ноды без значения по умолчанию (В-10), изменение
— 001.87; применение раздела — 001.80. Пакет nftables
и служба — `bootstrap.sh` (001.61). Передача счётчиков conntrack — 001.39 (метрики).

1. **TC-E2E-01:** Egress

2. **TC-E2E-02:** Лимит соединений

   - Ожидаемый результат: отклонены (правило AC-11)
3. **TC-E2E-03:** Частота новых входящих соединений
   - Входные данные: набор с M = 5 соединений в секунду загружен в network namespace на VM; с
     одного адреса — 20 новых соединений на порт inbound за секунду; с другого адреса — 3
   - Ожидаемый результат: сверх предела с первого адреса отклонены; все три со второго приняты
     (правило AC-40)
