# Задача 001.55: Node Agent: цикл long-poll, курсоры, снапшот, `resync_required`, `state_generation`

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-01 Ввод ноды в эксплуатацию
- UC-05 Исчерпание лимита и отзыв доступа
- UC-10 Восстановление Control Plane из резервной копии
- UC-11 Обновление парка нод

Требования RTM: R-04.

<!-- contract:goal -->

## Цель задачи

Реализовать цикл синхронизации: long-poll с курсорами, запрос полного снапшота при первом запуске,
раз в сутки, по расхождению контрольных сумм, по 409 и `resync_required`, сохранение курсоров,
`generation` и раздела `agent` в Store, `Ack` после применения, backoff при ошибках.

## Описание изменений

### Новые файлы

- `node-agent/internal/sync/loop_test.go` — тест против тестового Control Plane

### Изменения в существующих файлах

#### Файл: `node-agent/internal/sync/loop.go`

- `Run(ctx, deps)`: `State → apply → Ack`; 409 → `full=1`; `resync_required` → `full=1`; курсоры в Store
- `generation` — непрозрачное значение: агент берёт его из каждого ответа 200 и из
  `details.generation` ответа 409 `generation_mismatch`, сохраняет в Store и затем запрашивает
  `full=1` с этим значением; первый запрос — с 0
- снапшот (`full=1`) запрашивается: при первом запуске (курсоров в Store нет); раз в сутки со
  случайной фазой; при расхождении `config.checksum` с канонической записью полученного
  `config.json` (Go: `json.Encoder` с `SetEscapeHTML(false)`, README `contracts/agent_v1`
  «Контрольная сумма конфигурации»); при расхождении `users.checksum` с суммой локального
  состава (поле и каноническая запись — 001.75b); по 409 (`generation_mismatch`, `cursor_ahead`)
  и `resync_required`
- ответ на `full=1` с `users.full = false` (вентиль по статусу ноды урезал состав) — повтор
  снапшота с выдержкой, растущей до 300 с, а не опрос в цикле
- неизвестные поля и разделы ответа состояния игнорируются; ответ без раздела, обязательного по
  контракту agent_v1 (например, `users` или `generation`), не применяется: ошибка разбора, запись
  в журнал, повтор запроса с выдержкой (backoff 001.54), курсоры и Store не меняются. Новый
  обязательный раздел вводит новая версия пути (`/agent/v2`); признака неизвестного раздела в
  heartbeat и перевода ноды в `degraded` нет (решение заказчика 2026-10-25, В-14)
- раздел `agent` ответа состояния (параметры агента вне документа Xray, со своим курсором версии;
  контракт — 001.26) принимается и сохраняется в Store; применение — 001.80
- применённую версию раздела `agent` агент передаёт в каждом запросе состояния рядом с
  `config_version` (имя параметра объявляет 001.26 в README `contracts/agent_v1`); отставание по
  ней — повод ответить long-poll, как по `config_version` (001.75c)

#### Файл: `node-agent/internal/store/store.go`

- реализация SQLite: схема и миграции, курсоры потоков, `generation`, раздел `agent` и его
  применённая версия; остальные задачи этапа 9 дополняют схему своими таблицами

### Интеграция компонентов

Применение конфигурации, состава и раздела `agent` — 001.80. Смысл `generation`, поле
`users.checksum` и правила снапшота закрепляет в контракте 001.75b, удержание long-poll — 001.75c;
эта задача зависит от обеих. Снятие `resync_required` после подтверждения полного ответа — 001.75.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Снапшот по поколению
   - Входные данные: ответ 409 `generation_mismatch` с `details.generation`
   - Ожидаемый результат: следующий запрос `full=1` с `generation` из `details`; курсоры сброшены;
     повторного 409 нет
2. **TC-E2E-02:** Курсоры сохраняются
   - Входные данные: перезапуск агента
   - Ожидаемый результат: запрос с сохранёнными курсорами и применённой версией раздела `agent`
3. **TC-E2E-03:** Поводы снапшота
   - Входные данные: первый запуск без курсоров; ответ, чей `config.checksum` не совпал с
     канонической записью `config.json`
   - Ожидаемый результат: в обоих случаях следующий запрос — `full=1`

### Модульные тесты

1. **TC-UNIT-01:** Обработка ответа без изменений
   - Проверяемая функция: `internal/sync::handleState`
   - Входные данные: 204
   - Ожидаемый результат: курсоры без изменений; немедленный следующий запрос
2. **TC-UNIT-02:** Выдержка при неполном снапшоте
   - Проверяемая функция: `internal/sync::handleState`
   - Входные данные: ответы на `full=1` с `users.full = false` подряд
   - Ожидаемый результат: выдержка перед каждым повтором растёт и не превышает 300 с
3. **TC-UNIT-03:** Ответ без обязательного раздела
   - Проверяемая функция: `internal/sync::handleState`
   - Входные данные: ответ 200 без раздела `users`; затем ответ с неизвестным разделом
   - Ожидаемый результат: первый не применён — ошибка `ErrMissingSection` в журнале, курсоры без
     изменений, следующий запрос — после выдержки; второй применён, неизвестный раздел пропущен
