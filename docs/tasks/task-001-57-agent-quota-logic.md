# Задача 001.57: Node Agent: локальный грант квоты и автономное отключение

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-05 Исчерпание лимита и отзыв доступа

Требования RTM: R-26.

<!-- contract:goal -->

## Цель задачи

Реализовать учёт `quota_grant_bytes` по пользователю в единицах списания: уменьшение по дельтам с
коэффициентом ноды, проверку остатка не реже раза в 5 с, запрос следующего гранта при 50 %,
применение гранта по номеру выдачи, локальный перевод в `suspended_quota` (`RemoveUser` +
стратегия разрыва) при исчерпании без связи. Для пользователей тарифа Unlimited локального предела
нет: Н-17в действует только для тарифов с лимитом (решение заказчика 2026-10-25, В-6).

## Описание изменений

### Новые файлы

- `node-agent/internal/quota/quota_test.go` — без связи: пользователь отключён при исчерпании гранта; при связи — новый грант заменяет остаток

### Изменения в существующих файлах

#### Файл: `node-agent/internal/quota/quota.go`

- `type Tracker`: остаток гранта в Store; `OnDelta(user, bytes)`; `RequestIfNeeded`; `OnExhausted` → 001.60
- расход гранта — в единицах списания: `floor((uplink + downlink) × multiplier_milli / 1000)` по
  дельтам пользователя; `multiplier_milli` — действующий коэффициент ноды из раздела `agent`
  ответа состояния; `consumed_bytes` запроса гранта — в тех же единицах
- остаток проверяется по снятию счётчиков с периодом не больше 5 с, независимо от 60-секундного
  интервала отчёта
- грант из строки состава применяется, только если `quota_issued_seq` строки больше номера уже
  применённого гранта; грант из ответа `quota/request` — по `issued_seq` по тому же правилу.
  Пользователь, исчерпавший грант локально, остаётся вне inbound до гранта с большим номером,
  даже если строка пришла с `state: active`
- отказ 404 `user_not_on_node` (пользователь вне состава ноды) — без повтора
- пользователь тарифа Unlimited — грант без ограничения: строка состава и ответ `quota/request`
  несут `quota_grant_bytes: null` с очередным номером выдачи (изменение контракта agent_v1 в
  001.36, фикстура `quota-request-unlimited.json`). `null` — не 0: поле гранта в Go — указатель,
  `nil` — грант без ограничения. С таким грантом агент не ведёт остатка, не запрашивает грант и
  не отключает пользователя по исчерпанию, в том числе без связи с Control Plane (Н-7); доступ
  снимает только строка состава с состоянием, снимающим доступ (решение заказчика 2026-10-25, В-6)
- грант `null` применяется по тому же правилу номера, что и конечный. Смену тарифа между Unlimited
  и тарифом с лимитом Control Plane передаёт новым грантом с большим номером на каждой ноде
  пользователя (`reissue`, 001.36): конечный грант после `null` начинает учёт остатка с размера
  гранта; `null` после конечного снимает остаток, и строка `active` возвращает в inbound
  пользователя, исчерпавшего грант локально

### Интеграция компонентов

Грант приходит в строке потока состава (цикл — 001.55, применение строки — 001.80) и по ответу
`quota/request`. Поле `quota_issued_seq` строки состава, отказ `user_not_on_node` и
`quota_grant_bytes: null` для Unlimited (В-6) вводит в контракт 001.36; раздел `agent` с
`multiplier_milli` — 001.26 (контракт) и 001.36 (значение).

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Автономное отключение
   - Входные данные: Control Plane недоступен; коэффициент 1.0; грант 256 МБ; передача 300 МБ
   - Ожидаемый результат: пользователь удалён из inbound; установленные соединения разорваны
     стратегией 001.60; перерасход не больше 256 МБ + полоса × (5 с + Н-17а) (AC-09; решение
     заказчика 2026-10-25, В-49)

### Модульные тесты

1. **TC-UNIT-01:** Порог запроса
   - Проверяемая функция: `internal/quota::needRequest`
   - Входные данные: израсходовано 49 % / 51 %
   - Ожидаемый результат: ложь / истина
2. **TC-UNIT-02:** Расход с коэффициентом
   - Проверяемая функция: `internal/quota::OnDelta`
   - Входные данные: `multiplier_milli` = 2000; дельта пользователя 100 МБ
   - Ожидаемый результат: остаток гранта уменьшился на 200 МБ
3. **TC-UNIT-03:** Повтор строки с прежним номером
   - Проверяемая функция: `internal/quota::ApplyRowGrant`
   - Входные данные: строка с тем же `quota_issued_seq` (дельта `blocked_ips`, снапшот), в том
     числе с `state: active` для пользователя, исчерпавшего грант локально
   - Ожидаемый результат: остаток не сброшен; пользователь вне inbound
4. **TC-UNIT-04:** Unlimited без предела
   - Проверяемая функция: `internal/quota::OnDelta`
   - Входные данные: строка `active` с `quota_grant_bytes: null`; Control Plane недоступен;
     дельты пользователя на 1 ГБ; затем ответ фикстуры `quota-request-unlimited.json`
   - Ожидаемый результат: `OnExhausted` не вызван; запроса гранта нет; пользователь в inbound;
     ответ с `null` разобран как грант без ограничения, а не как 0
5. **TC-UNIT-05:** Смена тарифа между Unlimited и тарифом с лимитом
   - Проверяемая функция: `internal/quota::ApplyRowGrant`
   - Входные данные: пользователь исчерпал конечный грант локально; строка `active` с
     `quota_grant_bytes: null` и большим `quota_issued_seq`; затем строка `active` с конечным
     грантом 256 МБ и ещё большим номером
   - Ожидаемый результат: после `null` пользователь в inbound, остатка нет; после конечного гранта
     остаток 256 МБ

### Регрессионные тесты

- Команда: `cd node-agent && go test ./internal/quota/...`
- Полный набор: `make test` — существующие тесты проходят.
