# Задача 001.63: Web: экраны кабинета — подписка, QR, статистика, мастер, профиль

Тип задачи: `[LOGIC IMPLEMENTATION]`.

## Связь со сценариями
- UC-16 Работа в личном кабинете
- UC-02 Регистрация и активация подписки Redeem-кодом

Требования RTM: R-08, R-09, R-10, R-11, R-12, R-53.

<!-- contract:goal -->

## Цель задачи

Реализовать mobile-first экраны §4.2, §4.12, §17.6: регистрация и вход, состояние подписки,
копирование ссылок на двух доменах, QR, перевыпуск с предупреждением, статистика по нодам и странам,
мастер первого подключения, профиль.

## Описание изменений

### Новые файлы

- `web/apps/cabinet/src/pages/*.test.tsx` — тесты компонентов с mock API из фикстур OpenAPI

### Изменения в существующих файлах

#### Файл: `web/apps/cabinet/src/pages/*`

- реализация экранов; QR через `qrcode`; deep-link импорта по платформе
- экран регистрации показывает версию правил использования (AUP) и ссылку на их текст; версия уходит в `aup_version` регистрации
- режим регистрации — поле `registration_mode` ответа `GET /auth/aup` (001.69; решение заказчика
  2026-10-25, В-31): `open` — форма без поля кода; `invite` — форма с полем Redeem-кода, значение
  уходит в `code` регистрации (001.20); `closed` — форма недоступна, вместо неё — сообщение о
  закрытой регистрации (AC-43). Ответ 403 `invite_required` на регистрацию без кода показывает
  поле кода и при режиме, прочитанном до смены настройки
- после регистрации экран «проверьте почту» с действием «отправить письмо ещё раз»: запрос
  `POST /auth/verify-resend` с адресом регистрации (001.16; решение заказчика 2026-10-25, В-32);
  ответ 202 — нейтральное сообщение «если адрес зарегистрирован и не подтверждён, письмо
  отправлено»; ответ по порогу §5.12 — сообщение о повторе позже. Тот же экран открывается со
  входа по ссылке «не пришло письмо подтверждения»
- экран подтверждения адреса по ссылке письма вызывает `POST /auth/verify` (001.14) и переводит на
  экран входа; вход завершает регистрацию (AC-43, серверная часть — 001.14)
- профиль: «выход на всех устройствах» отзывает все сессии, включая текущую (`docs/architectures/security.md` §7.1); после ответа кабинет переходит на экран входа
- главный экран и профиль показывают предупреждение «письма на ваш адрес не доставляются», если
  `/me` отдаёт `email_undeliverable_at` (решение заказчика 2026-10-25, В-37)

### Интеграция компонентов

Данные — `/api/v1/me/*` (001.16). Версию правил, ссылку на текст и режим регистрации отдаёт
`GET /auth/aup` (001.69) — зависимость от 001.69. Регистрация, подтверждение адреса и вход —
маршруты `/auth/*` 001.14; поле `code` регистрации — 001.20 (зависимость 001.63 → 001.20); повторная отправка
письма — 001.16. Поле `email_undeliverable_at` ответа `/me` — 001.16
(`docs/architectures/interfaces.md` §5.1), пометку ставит 001.78. Строки экранов — пакет `i18n`;
время экраны выводят только через `formatDateTime` в поясе профиля из ответа `/me` (001.65b) —
зависимость от 001.65b.

## Тестовые случаи

### Сквозные тесты

1. **TC-E2E-01:** Мастер подключения
   - Входные данные: мобильный `User-Agent` iOS
   - Ожидаемый результат: предложены Shadowrocket и Streisand; кнопка импорта; экран проверки (AC-30)
2. **TC-E2E-02:** Перевыпуск
   - Входные данные: нажатие «перевыпустить»
   - Ожидаемый результат: модальное предупреждение о разрыве устройств; после подтверждения новая ссылка
3. **TC-E2E-03:** Выход на всех устройствах
   - Входные данные: нажатие «выйти на всех устройствах»
   - Ожидаемый результат: `POST /auth/logout-all`; кабинет на экране входа
4. **TC-E2E-04:** Правила при регистрации
   - Входные данные: экран регистрации
   - Ожидаемый результат: показаны версия и ссылка AUP; запрос `/auth/register` несёт
     `aup_version` текущей версии
5. **TC-E2E-05:** Недоставляемый адрес
   - Входные данные: mock `/me` с `email_undeliverable_at`; без него
   - Ожидаемый результат: предупреждение показано; не показано
6. **TC-E2E-06:** Регистрация по приглашению
   - Входные данные: mock `GET /auth/aup` с `registration_mode = invite`; с `open` и ответом 403
     `invite_required` на регистрацию
   - Ожидаемый результат: в режиме `invite` поле Redeem-кода показано, запрос `/auth/register`
     несёт `code`; в режиме `open` поля нет до ответа 403, после него поле показано (В-31)
7. **TC-E2E-07:** Повторная отправка письма подтверждения
   - Входные данные: экран «проверьте почту»; нажатие «отправить письмо ещё раз»; mock ответа 202;
     mock ответа отказа по порогу §5.12
   - Ожидаемый результат: запрос `POST /auth/verify-resend` с адресом; нейтральное сообщение;
     сообщение о повторе позже (В-32)
8. **TC-E2E-08:** Регистрация завершается входом; закрытая регистрация
   - Входные данные: регистрация, переход по ссылке подтверждения, вход (mock ответов `/auth/*`);
     mock `GET /auth/aup` с `registration_mode = closed`
   - Ожидаемый результат: последовательность `register` → `verify` → `login`, после входа —
     главный экран кабинета; при `closed` формы регистрации нет, показано сообщение (AC-43)

### Модульные тесты

- [ ] AC-30 в части интерфейса

  Edge двух последних версий, iOS Safari 16 и новее, Android Chrome двух последних версий и
  встроенные браузеры Telegram и Instagram на iOS и Android
