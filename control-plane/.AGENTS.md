# Directory: control-plane/

## Purpose
Control Plane (Python 3.14, FastAPI): пакет `app/` в трёх ролях процесса, миграции, тесты и
образ Docker. Карта пакета — `app/.AGENTS.md`.

## Files

### [pyproject.toml]
- Метаданные, зависимости `[project]` и `[dev]`, настройки ruff / mypy strict / pytest
  (`python_files = test_*.py` — единственный источник правил обнаружения для `make test-py`).

### [requirements-dev.lock]
- `pip freeze` venv разработки (`make setup`): рантайм + инструменты.

### [requirements.lock]
- Рантайм-зависимости образа — `pip freeze` чистого venv без `[dev]`; версии совпадают с
  `requirements-dev.lock`. Только готовые колёса (`--only-binary=:all:`).

### [Dockerfile]
- Образ C-01…C-03 на `python:3.14-slim`, пользователь `app` (uid 10001), зависимости из
  `requirements.lock`, приложение запускается из `/app` без установки пакета (разработка
  подменяет `/app/app` монтированием). `EXPOSE 8000`; `ENTRYPOINT docker-entrypoint.sh`.

### [docker-entrypoint.sh]
- Стартует от root: копирует секреты из `/run/host-secrets` в `/run/secrets` (владелец `app`,
  0400) и переключается на `app` через `setpriv`. Выбор роли по `APP_ROLE`: `api` →
  `uvicorn app.main:create_app --factory` (`APP_WORKERS`, `APP_RELOAD`; имена `UVICORN_*` не
  используются — их читает сам uvicorn); `worker-critical|worker-background` →
  `python -m app.jobs.worker --queue …`; `scheduler` → `python -m app.jobs.scheduler`. Аргументы
  командной строки выполняются как есть (`docker compose run api python -m app.cli …`).
  Задача 001.03 добавляет миграции (`MIGRATE_DSN`, `MIGRATE_PASSWORD_FILE`) перед `api`.

### [.dockerignore]
- Контекст сборки: `app/`, `migrations/`, `yoyo.ini`, `requirements.lock`, `docker-entrypoint.sh`.

### [yoyo.ini]
- Конфигурация CLI yoyo: `sources = migrations`, `database = %(MIGRATE_DSN)s` (для CLI — полный
  URL с паролем и схемой `postgresql+psycopg://`), `batch_mode = on`.

### [migrations/]
- `bootstrap/roles.sql` — роли `app_owner` (владелец базы, без входа), `app_rw`, `app_migrate`
  (член `app_owner`), `app_backup`; psql-переменные `:db`, `:rw`, `:mig`, `:bk`. Кластерные
  объекты: выполняется при инициализации кластера (`deploy/compose/postgres/initdb.d`) или в CI,
  не миграцией.
- `0001_extensions_roles_enums.sql` / `.rollback.sql` — `btree_gist`, `citext`, привилегии по
  умолчанию `app_rw`/`app_backup`, 22 перечисления §4.2. Каждая миграция начинается с
  `SET LOCAL ROLE app_owner` — владелец объектов `app_owner`, учёт yoyo ведёт `app_migrate`.
- `040_schema_identity.sql` / `.rollback.sql` — `users` (citext email, uuid v7), `admin_users`,
  `admin_recovery_codes`, `email_tokens`, `auth_events` (партиции по суткам `ts`, `id` из
  `auth_events_id_seq`; партиции создаёт функция 001.08). `-- depends: 0001_…`.
- Правила: пары apply/rollback, expand/contract (§4.6); перечисления только расширяются;
  нумерация — `0001` bootstrap-миграция, далее `NN0_…` по номеру задачи плана (040 = 001.04).

### [tests/]
- `conftest.py`: фикстуры `pg_dsn` (`app_rw`), `redis_url` (стенд по `PG_DSN`/`REDIS_URL`),
  `app_client` (после 001.10).
- `e2e/_cli.py`: `run_cli()` и `migration_count()` — общие помощники сквозных тестов миграций;
  `e2e/_spec.py`: ожидания по модели данных (`EXPECTED_ENUMS`).
- `e2e/test_migrations.py`: TC-E2E-01 задачи 001.03 — `app.cli migrate`, `--rollback-all`,
  повторное применение; владельцы всех объектов `public`, значения перечислений, записи
  `pg_default_acl`, `has_function_privilege` для `app_backup`/`app_rw`; статический страж
  `SET LOCAL ROLE`. Без базы тесты падают с ошибкой подключения, не пропускаются.
- `e2e/test_schema_identity.py`: задача 001.04 — `--rollback` на один шаг, ограничения §4.2.1 под
  `app_rw` (UNIQUE citext, FK, enum, CASCADE, третий язык принимается), `auth_events`: без
  партиции строка отклоняется, вставка под `app_rw` во временную партицию 2000-01-01 (вне окна
  планировщика 001.08; создаёт и удаляет `app_owner`).
- `unit/db/test_schema_identity.py`: сверка каталогов с §4.2.1 (колонки, ограничения, индексы,
  ключ партиционирования, последовательность), права `app_rw`/`app_backup` на таблицы и на
  `auth_events_id_seq` по `has_table_privilege`/`has_sequence_privilege` (`information_schema`
  из сессии `app_rw` чужих прав не видит).

## Conventions
- Секреты только файлами (`*_FILE` в окружении: `PG_PASSWORD_FILE`, `MIGRATE_PASSWORD_FILE`,
  `APP_ENCRYPTION_KEY_FILE`, `CA_KEY_FILE`, `SMTP_PASSWORD_FILE`), адреса служб — `PG_DSN`
  (роль `app_rw`), `MIGRATE_DSN` (роль `app_migrate`), `REDIS_URL` (§10.3).
- Миграции — только через `python -m app.cli migrate` (yoyo API, блокировка) или CLI yoyo с
  `yoyo.ini`; SQL к базе без ORM (asyncpg в приложении, psycopg 3 у yoyo).
- Обновление `requirements*.lock` — вместе, из одного pyproject.
