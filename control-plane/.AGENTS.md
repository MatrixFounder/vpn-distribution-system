# Directory: control-plane/

## Purpose
Control Plane (Python 3.14, FastAPI): пакет `app/` в трёх ролях процесса, миграции, тесты и
образ Docker. Карта пакета — `app/.AGENTS.md`.

## Files

### [pyproject.toml]
- Метаданные, зависимости `[project]` и `[dev]`, настройки ruff / mypy strict / pytest
  (`python_files = test_*.py` — единственный источник правил обнаружения для `make test-py`).

### [requirements-dev.lock]
- `pip freeze` venv разработки (`make setup`): рантайм + инструменты.

### [requirements.lock]
- Рантайм-зависимости образа — `pip freeze` чистого venv без `[dev]`; версии совпадают с
  `requirements-dev.lock`. Только готовые колёса (`--only-binary=:all:`).

### [Dockerfile]
- Образ C-01…C-03 на `python:3.14-slim`, пользователь `app` (uid 10001), зависимости из
  `requirements.lock`, приложение запускается из `/app` без установки пакета (разработка
  подменяет `/app/app` монтированием). `EXPOSE 8000`; `ENTRYPOINT docker-entrypoint.sh`.

### [docker-entrypoint.sh]
- Стартует от root: копирует секреты из `/run/host-secrets` в `/run/secrets` (владелец `app`,
  0400) и переключается на `app` через `setpriv`. Выбор роли по `APP_ROLE`: `api` →
  `uvicorn app.main:create_app --factory` (`APP_WORKERS`, `APP_RELOAD`; все `UVICORN_*` точка
  входа снимает до запуска — опции, которых нет в строке запуска, uvicorn взял бы из них, а
  `.env` оператора роли получают целиком; раунд 8); `worker-critical|worker-background` →
  `python -m app.jobs.worker --queue …`; `scheduler` → `python -m app.jobs.scheduler`.
  Аргументы командной строки выполняются как есть (`docker compose run api python -m
  app.cli …`). Перед `api` выполняются миграции (`MIGRATE_DSN`, `MIGRATE_PASSWORD_FILE`, 001.03);
  роль `api` поднимается с `--proxy-headers --forwarded-allow-ips '*'` (заголовки
  перезаписывает nginx — см. `tests/unit/test_proxy_contract.py`) и `--no-access-log` (журнал
  запросов ведёт nginx, где путь `/s/` исключён: access-log uvicorn писал токен подписки — Н-25,
  001.25, раунд 6; страж `test_uvicorn_writes_no_access_log`) и `--ws none` (маршрутов WebSocket
  нет, а строки рукопожатия uvicorn пишет с путём мимо access-log, раунд 7) и `--log-level info`
  (уровень trace включает журнал сообщений ASGI с путём, раунд 8) и `--lifespan on` (пару CA
  проверяет lifespan приложения: с `off` api стартовал бы здоровым с негодным CA, раунд 9) и
  проходит healthcheck
  `/healthz`. Перед `setpriv` задаётся `HOME=/app USER=app`: с унаследованным `HOME=/root`
  asyncpg падал на поиске `~/.postgresql/` (001.11).

  промежуточных CA); путь с управляющими символами — map `$uri_has_control` (страж вычисляет её
  на каждом коде C0 и DEL в конце и в середине пути) и первое правило каждого server: 8443/8444 —
  `rewrite ^ /__not_found last` в `location = /__not_found` ровно с `client_max_body_size 0;
  try_files /nonexistent =404;`, публичный — `return 404;`; отказы 404, 411 и 413 на 8443/8444 —
  `try_files` после пределов, `return` — только в именованных location, `rewrite` — только три
  перехода в служебные location (`/__not_found`, `/__length_required`, `/__too_large`), `internal` нет
  (внешнему запросу к нему nginx отвечает 404 в фазе FIND_CONFIG, до пределов), у prefix- и
  точного location с `*_pass` на «/» — точный сосед без косой черты с `try_files` (иначе
  auto_redirect — 301 в FIND_CONFIG); у переменной map писатель один — сама map: ни `set`, ни
  второй `map` (побеждает последний, имена без учёта регистра), ни `geo`, `split_clients`,
  `auth_request_set`, `perl_set`, `js_set`, `js_var`, ни именованной группы регулярного выражения
  в файле (переменные map изменяемы; писатели — по дереву директив, 001.25, раунды 6–8); первое
  правило каждого server — первая директива модуля rewrite уровня server (любая форма `if`,
  `return`, `rewrite`, `break`), `break` в файле запрещён; `access_log` ниже уровня http —
  только `off`, `error_log` — не мягче `warn`; путь `/s/` там, куда его отдаёт nginx: на
  публичном — location без журналов (`error_log /dev/null`) и временных файлов, на Node API —
  без апстрима (`test_the_request_log_is_declared_only_at_the_http_level`); карта `$log_referer` — «-» в любом
  написании `/s/`; тела без известной длины — map `$body_without_length` с двумя правилами на уровне
  http (`Transfer-Encoding` при любом методе; отсутствие длины у любого метода, кроме GET и HEAD),
  `if … rewrite ^ /__length_required last` в служебный `location` с `try_files /nonexistent
  =411` (отказ после пределов, 001.25) и `error_page 411 = @length_required` на уровне обоих
  server Node API, тело единого формата без `Retry-After`, внешнему запросу к служебному пути —
  404 веткой по `$body_without_length`; тело длиннее предела location — карты
  `$content_length_over_64k`, `$content_length_over_1m` и `$agent_body_too_large` по
  `Content-Length` (страж выводит пороги из `client_max_body_size` каждого location и подаёт на
  карты таблицу длин по путям обоих server, в том числе путь отчётов с `\n` и `\r` в конце —
  шаблоны закреплены `\z`), `if … rewrite ^ /__too_large last` в служебный
  `location` без предела тела с `try_files /nonexistent =413` и `error_page 413 = @too_large`
  (страница nginx, как в контракте; прямому запросу к служебному пути — 404 единого формата
  единственной веткой по карте `$too_large_requested_directly`, страж вычисляет её ключи); якорь клиента —
  только `ssl_client_certificate` (`ssl_trusted_certificate` и `ssl_conf_command` на уровне
  http и на 8443 запрещены); публичный server правил длины тела не несёт;
  `proxy_request_buffering on` объявлен на уровне http один раз и нигде не переопределён
  (трактовка Н-4 по `urt`), `proxy_buffering on` так же, `proxy_max_temp_file_size 8m` (на server Node API не переопределён, в location подписки — 0), `proxy_connect_timeout 2s`, `proxy_send_timeout 10s`, `proxy_intercept_errors` не включён, `resolver_timeout 5s`,
  `limit_req_log_level`/`limit_conn_log_level notice`; Н-25 — `access_log … if=$loggable`,
  `$loggable` из map по `$uri`, по признаку служебного `$uri` своего server (карта по
  `$server_port`: служебные пути — ровно цели `rewrite` каждого server, у публичного их нет) и по
  сырой `$request` до «?» и «#» — сырой ключ читается только у служебного `$uri` (косая вокруг
  «s» — и `%2F`; `$request_uri` в файле нет), и по пустому `$uri` при любом статусе (отвергнут до
  разбора: 400, 408, 414, 505 — формат без строки запроса); страж собирает ключи карт из их
  источников в файле и подаёт таблицу «строка запроса, `$uri` журнала, статус, порт», в том
  числе `#/s/`, сегмент `/s/` без перехода и путь, нормализованный в служебный, на публичном
  (001.25, раунды 6, 8, 9), `access_log off` и `Referrer-Policy` в `location ^~ /s/`, основной
  формат пишет `$log_referer`; `$uri` меняют только шесть переходов `rewrite` 8443/8444:
  `error_page` — только в именованный location, `try_files` — проба `/nonexistent` и код, каждый
  location решает сам и у каждого server есть `location /` (отдачи файлов и `index` нет), один
  `proxy_ignore_headers X-Accel-Redirect` на уровне http, апстрим — только `proxy_pass`, модулей
  скриптов и `load_module` нет (`test_only_the_service_rewrites_change_the_uri`, раунд 9); гейт бюджета Н-4 (по `urt`): бюджет читается из строки Н-4
  `docs/idea.md` (и равен 200), число элементов части равно измеренному (`MEASURED_ELEMENTS`
  3 000 при 500/2 500), константа стоимости элемента (p95 замера стенда, согласована с замером)
  × элементов × число частей на парк + операции остальных видов за окно разбора
  (`ceil(окно × частота) + 1` по зоне парка и по зоне enrollment — три и две) × стоимость операции (парка — 4 мс, самый дорогой путь отказа, равен замеру; enrollment — 12 мс: наибольшее из консервативной оценки — стенка в процессе api самого дорогого пути плюс тихий `urt` контроля — и p95 `urt` путей, приведённого контролем своей серии, с округлением вверх, 001.25) ≤ 200 − резерв (нижняя граница резерва, худшее тело отчёта в пределах формы 37 мс не дороже приёма, модель пар не ниже замера пар), частота парка × стоимость + enrollment ≤ четверти цикла, отчёты на предельной пропускной способности плюс остальные ≤ одного цикла (подъём предела части, частоты парка или
  стоимости красный по бюджету, а не по литералу); 429 — `error_page 429 = @rate_limited` на
  уровне обоих server, ни в одном `location` нет своего `error_page`, тело единого формата и
  `Retry-After` (`always`); `log_format` несёт времена запроса и апстрима; у `nginx` и `api` —
  `mem_limit` = `memswap_limit`, `cpus` (nginx 1.0, api 2.0) и `pids_limit` (nginx 256, api 512)
  в базовом Compose
  (разбор YAML: якоря, слияния, потоковая запись), список файлов — из команды запуска в шапке
  базового файла, и та же команда в `deploy/README.md`; любой другой `*.y*ml` в каталоге,
  `include:` и `extends:` — отказ, оверлей не задаёт пределов, `cpus`/`pids_limit`, `logging`
  и томов nginx, `deploy.resources` не применяется; временные файлы nginx — tmpfs на
  `/var/cache/nginx` с размером из файла (64m, меньше потолка памяти), оба пути временных
  файлов (`client_body_temp_path`, `proxy_temp_path`) под точкой монтирования; журналы всех
  служб ограничены `json-file` в базовом файле, и ни один оверлей не переопределяет
  `logging`; `command`/`entrypoint` — только у postgres и redis (роль приложения с ними обошла
  бы `docker-entrypoint.sh`: флаги uvicorn, миграции, копирование секретов — 001.25, раунд 7);
  `ports` — список разрешений `ALLOWED_PORTS` по службам (четыре порта nginx,
  postgres и redis — только на литеральном `127.0.0.1`, у остальных служб — ни одного); самое
  большое допустимое тело
  строится из самих пределов модели и самых широких канонических форм (наборы полей —
  равенством: новое поле пересчитывает предел), его размер закреплён числом (457 369 Б —
  стенд строит то же тело), помещается в предел, а предел не дальше 1 МиБ от него.

## Conventions
- Секреты только файлами (`*_FILE` в окружении: `PG_PASSWORD_FILE`, `MIGRATE_PASSWORD_FILE`,
  `APP_ENCRYPTION_KEY_FILE`, `CA_KEY_FILE`, `SMTP_PASSWORD_FILE`), адреса служб — `PG_DSN`
  (роль `app_rw`), `MIGRATE_DSN` (роль `app_migrate`), `REDIS_URL` (§10.3).
- Миграции — только через `python -m app.cli migrate` (yoyo API, блокировка; `--break-lock`
  после клиента, умершего посреди миграции; `--unmark ID` после клиента, умершего между откатом
  и снятием отметки — самопроверка `migrate` укажет на такую отметку кодом 65) или CLI yoyo с
  `yoyo.ini`; SQL к базе без ORM (asyncpg в приложении, psycopg 3 у yoyo).
- Обновление `requirements*.lock` — вместе, из одного pyproject.
