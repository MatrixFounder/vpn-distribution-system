# Directory: control-plane/app/api/

## Purpose
Внешний API `/api/v1` (interfaces.md §5.1): кабинет пользователя и панель администратора. Стиль
REST/JSON, версия в пути, сессионная cookie (§7.1), единый формат ошибок (`app/errors.py`).

## Files

### [router.py]
- `router = APIRouter(prefix="/api/v1")`: подключает `auth` из `auth.py` (с зависимостью
  `redis_required` — fail-closed §9.1) и подроутеры `me` (`/me`), `admin` (`/admin`) с заглушками
  501 `not_implemented` (`GET /me`, `GET /admin/dashboard`). STUB-задачи добавляют маршруты
  разделов §5.1 в свои модули и включают их сюда; LOGIC-задачи заменяют заглушки реализацией.

### [auth.py]
- Раздел `/auth` (001.13): `register` 201, `verify` 200, `login` 200 + cookie `sid` (§7.1, через
  `security.sessions.set_session_cookie`) либо 401 `invalid_credentials` без cookie, когда
  `authenticate` возвращает `None`; `logout`/`logout-all` 204 со снятием cookie теми же
  атрибутами; `reset-request` 202 для любого адреса (UC-15 A1 — статус, тело и заголовки
  одинаковы); `reset-confirm` 200; без Redis все семь → 503 (fail-closed через роутер). Схемы:
  тела наследуют `StrictModel` (`extra="forbid"`) — `RegisterIn`, `VerifyIn`, `LoginIn`,
  `ResetRequestIn`, `ResetConfirmIn`; адрес без пробелов и управляющих символов, пароль 8…256;
  ответ `StatusOut` со `status: Literal[...]` (enum в OpenAPI). Зависимость `get_user_service()`
  → `domain.users.UserService` (заглушка принимает любые учётные данные — долг 001.14). Логика,
  `require_csrf`, лимиты — 001.14.

## Conventions
- Один модуль на раздел §5.1 (`auth.py`, `me.py`, `admin/*.py`); `router.py` только собирает.
- Каждая операция декларирует одно разрешение матрицы «роль × операция» (R-35, задача 001.46).
- Ответы и запросы — pydantic-схемы; ошибки — `ApiError`, никогда `HTTPException` напрямую.
