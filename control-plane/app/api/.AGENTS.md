# Directory: control-plane/app/api/

## Purpose
Внешний API `/api/v1` (interfaces.md §5.1): кабинет пользователя и панель администратора. Стиль
REST/JSON, версия в пути, сессионная cookie (§7.1), единый формат ошибок (`app/errors.py`).

## Files

### [router.py]
- `router = APIRouter(prefix="/api/v1")`: подключает `auth` из `auth.py`, `me` из `me.py` и
  `admin` из пакета `admin/` — все три с зависимостью `redis_required` (fail-closed §9.1: лимиты
  и сессии живут в Redis). STUB-задачи добавляют маршруты разделов §5.1 в свои модули и включают
  их сюда; LOGIC-задачи заменяют заглушки реализацией.

### [admin/]
- `__init__.py` — роутер `/admin`: `GET /dashboard` (заглушка 501 под сессией администратора,
  001.44) и подроутеры `plans`, `groups`, `codes` (001.18), `nodes` (001.24). `_common.py` — `Admin =
  Depends(current_admin)`, `CSRF = [Depends(require_csrf)]`, `permission(name)` →
  `openapi_extra={"x-permission": name}` — одно разрешение на операцию (R-35), проверка по
  матрице — 001.46.
- `plans.py` — `GET/POST /plans`, `PATCH/DELETE /plans/{plan_id}` (удаление = архивирование,
  UC-09 A4) на `PlanService`; `groups.py` — CRUD `/groups/access`, `/groups/billing`, `POST
  /groups/billing/{group_id}/multiplier` на `GroupService`; `codes.py` — `POST /codes`, `POST
  /codes/batch` (`BatchIn(count 1…10000, spec)` → `BatchOut`), `GET /codes/batch/{batch_id}/export`
  (`text/csv` с CRLF, заголовок `code,expires_at,plan`, `Content-Disposition: attachment`,
  `Cache-Control: no-store`), `GET /codes/{code_id}/redemptions` на `CodeService`. Все операции под сессией администратора, мутации под CSRF; заглушки 001.18,
  логика — 001.19 (тарифы, группы), 001.20 (коды).
- `nodes.py` — `GET/POST /nodes`, `GET/PATCH/DELETE /nodes/{node_id}` (удаление = вывод из
  эксплуатации §4.6, 204), `POST /nodes/{node_id}/bootstrap-token` (201 `BootstrapToken`,
  UC-01 шаги 2–3), `POST …/approve` (`pending` → `provisioning`, шаг 7), `POST …/status`
  (`ManualStatusIn`: ручной статус или `null` — снятие), `POST …/revoke-identity` (Н-31,
  `NodeState` с `revoked_at`), `GET …/state` (`NodeState`: курсоры, heartbeat, версии,
  identity — сверка UC-01 шаг 6) на `NodeService`; разрешения `nodes.read|write`; заглушки
  001.24, логика — 001.25 (enrollment, отзыв), 001.30 (статусы по heartbeat); inbound и команды
  ноды — 001.26, 001.28.

### [me.py]
- Раздел `/me` (001.15, заглушки; логика 001.16/001.17/001.20): восемь операций под сессией
  пользователя (`User = Depends(current_user)`; без сессии 401 `unauthenticated`): `GET /me` →
  `Profile`, `PATCH /me` (`ProfileUpdateIn`: язык `en|ru`, пояс IANA по `zoneinfo`, согласие) →
  `Profile`, `DELETE /me?confirm=true` → 204, `GET /me/subscription` → `SubscriptionOut` (состояние
  `subscription_state`, тариф, период, лимит/остаток, `links` на каждом домене
  `SUBSCRIPTION_DOMAINS`), `POST /me/subscription/redeem` (`RedeemIn`), `POST
  /me/subscription/reissue?confirm=true` → новая ссылка, `GET /me/traffic?period=<uuid>` →
  `TrafficStats` (`accounting/stats.py`), `GET /me/onboarding` → `OnboardingOut` (платформа,
  клиенты §4.2, `import_url`, `qr_payload`, проверка соединения). Мутации — под `require_csrf`
  (403 `csrf_failed`); перевыпуск и удаление без `confirm=true` — 409 `confirmation_required`
  (`details.warning`, `details.confirm`) через `confirmation_required()`. Фиксированные значения:
  `stub_subscription()`, `STUB_TOKEN`/`STUB_TOKEN_REISSUED`, `CLIENTS`; `subscription_links(token)`
  читает `Settings.read().subscription_domains` и падает `RuntimeError` при пустом списке;
  `IANA_TIMEZONES` — имена поясов один раз на процесс; `import_url` кодирует ссылку (`quote`);
  статистика получает подключение из пула (`Pool`).

### [auth.py]
- Раздел `/auth` (001.13 маршруты, 001.14 логика): `register` 201 (`UserService.register`:
  режимы `settings.registration_mode`, одноразовые домены, CAPTCHA, 409 `email_taken`; письмо
  `verify` в очередь), `verify` 200 / 410 `token_expired`, `login` 200 + cookie `sid` и `csrf`
  (§7.1, §7.3; сессия в `SessionStore`, TTL `USER_SESSION_TTL`) либо 401 `invalid_credentials`
  без cookie; `logout`/`logout-all` 204 (`Depends(require_csrf)`, отзыв сессии / всех сессий
  субъекта, снятие обеих cookie теми же атрибутами); `reset-request` 202 для любого адреса
  (UC-15 A1 — статус, тело, заголовки и путь кода одинаковы); `reset-confirm` 200 +
  `SessionStore.revoke_all` пользователя; без Redis все семь → 503 (fail-closed через роутер),
  без базы — 503 (`DatabaseUnavailable`). Лимиты §5.12 — `limit()`: превышение → 429
  `rate_limited` с `Retry-After` (секунды до освобождения окна) либо, где положена CAPTCHA и
  провайдер настроен (`captcha=` — `CaptchaAnswer` запроса, один вызов провайдера на запрос при
  любом числе порогов), 429 `captcha_required` без верного ответа; с CAPTCHA —
  `register` по адресу источника и домену почты и `login` по адресу источника; отказом —
  `verify`/`reset-confirm` (`TOKEN_IP`) и `reset-request` (по адресу почты). Порог входа по учётной записи считает только
  отказы: `peek` до пароля, `check` после неверного, `reset` после верного; над порогом с
  провайдером CAPTCHA проверяется до пароля, без провайдера порог не действует (ОВ-A3, объявлено).
  Адрес клиента — `client_ip()` из `request.client` (uvicorn ← nginx). Схемы: тела наследуют
  `StrictModel` (`extra="forbid"`, обрезка краевых пробелов) — `RegisterIn`, `VerifyIn`,
  `LoginIn`, `ResetRequestIn`, `ResetConfirmIn`; адрес без пробелов и управляющих символов,
  пароль 8…256, токен 16…512; ответ `StatusOut` со `status: Literal[...]` (enum в OpenAPI).
  Зависимости `get_user_service()` (пул), `get_session_store()`, `get_rate_limiter()` (Redis).

## Conventions
- Один модуль на раздел §5.1 (`auth.py`, `me.py`, `admin/*.py`); `router.py` только собирает.
- Каждая операция декларирует одно разрешение матрицы «роль × операция» (R-35, задача 001.46).
- Ответы и запросы — pydantic-схемы; ошибки — `ApiError`, никогда `HTTPException` напрямую.
