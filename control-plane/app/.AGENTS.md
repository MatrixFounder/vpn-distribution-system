# Directory: control-plane/app/

## Purpose
Приложение Control Plane (C-01 `api`, C-02 `worker`, C-03 `scheduler`) — один пакет Python,
запускаемый в трёх ролях. Границы модулей — по функциональным компонентам
`docs/architectures/functional-architecture.md`.

## Files

### [__init__.py]
- `__version__` — версия приложения (`info.version` в OpenAPI); поднимается при выпуске.

### [main.py]
- `create_app() -> FastAPI` (001.10): роутеры `/api/v1`, `/agent/v1`, `/s`, обработчики единого
  формата ошибок, `/healthz` (живость; готовность базы/Redis — 001.68), `/metrics` (текст
  Prometheus, до 001.68 один показатель), OpenAPI по `/openapi.json` без `/docs`. Сборка и
  lifespan к базе и Redis не обращаются; lifespan только закрывает пул и клиент. Точка входа
  uvicorn — `app.main:create_app --factory`.

### [config.py]
- `Settings` (pydantic-settings, alias = имя переменной): `PG_DSN`, `PG_PASSWORD_FILE`,
  `REDIS_URL`, `APP_ROLE`, `APP_ENV`, `LOG_LEVEL`, `SUBSCRIPTION_DOMAINS` (через запятую,
  `NoDecode`), `APP_ENCRYPTION_KEY_FILE`. `Settings.load()` читает окружение и проверяет файлы
  секретов (`SecretError` при отсутствии или пустоте — ошибка старта). `read_secret()`,
  `dsn_with_password()` — общие для приложения и `cli.py`; `pg_dsn_with_password` — DSN `app_rw`.

### [errors.py]
- `ApiError(code, message, status=, details=)` и `error_response()` — формат
  `{"error": {"code", "message", "details"}}` (interfaces.md §5.1); `install_error_handlers()`
  переводит в него `HTTPException` (404 `not_found`, 405 `method_not_allowed`, …),
  `RequestValidationError` (422 `validation_error`, `details.errors[loc, msg, type]`) и любые
  исключения (500 `internal_error` без подробностей, трассировка — в журнал).
  `not_implemented(operation)` — 501 заглушек STUB-задач.

### [metrics.py]
- `render()` — текст Prometheus для `/metrics`: `control_plane_up`, `control_plane_db_up`,
  `control_plane_jobs{queue,status}` (все пары, нули включены); база недоступна →
  `control_plane_db_up 0`, ответ не падает. Библиотека клиента — 001.68.

### [i18n.py]
- `negotiate(user, accept_language) -> str` — заглушка 001.10 (`en`); реализация — 001.65.

### [redis.py]
- `get_redis()` — один клиент `redis.asyncio` на процесс, создаётся лениво из `Settings`
  (таймауты 1 с / 2 с — fail-closed отвечает быстро); `close_redis()`. Клиент привязан к циклу
  событий: объект чужого цикла отбрасывается (тесты). Имя модуля совпадает с пакетом `redis`:
  внутри — только абсолютные импорты.

### [db/pool.py]
- `get_pool()` — один пул asyncpg на процесс под `app_rw` (лениво, `min_size=1`, `max_size=10`);
  `close_pool()`; `transaction(pool)` — подключение в транзакции (commit / rollback). Пул
  привязан к циклу событий: пул закрытого цикла обрывается и создаётся заново (тесты).

### [cli.py]
- `python -m app.cli migrate [--rollback | --rollback-all] [--break-lock]` — миграции yoyo из
  `../migrations` под ролью `app_migrate` (`MIGRATE_DSN` + `MIGRATE_PASSWORD_FILE` или полный
  URL), с блокировкой yoyo; вызывается точкой входа образа при старте роли `api` (§10.2).
  `migrate_dsn()` нормализует схему в `postgresql+psycopg` через `config.dsn_with_password()`.
  `python -m app.cli admin create` — заглушка до 001.47 (код 69).

## Conventions
- Python 3.14; SQL без ORM (asyncpg); настройки — `pydantic-settings`; проверки — `ruff`, `mypy --strict`.
- Ошибки API — только `ApiError` / `not_implemented()`; тело всегда `{"error": …}` (§5.1);
  `RateLimitUnavailable` → 503 с `Retry-After` (fail-closed §9.1) — роутеры операций с лимитом
  частоты подключают `Depends(redis_required)`.
- Новые роутеры регистрируются в `api/router.py`, `agent_api/router.py`, `subscription/router.py`;
  `main.py` подключает три корневых роутера и не знает о подроутерах.
- Пул и Redis — через `get_pool()` / `get_redis()`, без собственных подключений в модулях
  (исключения: подключение LISTEN исполнителя и сессия-держатель advisory-блокировки
  планировщика — намеренно вне пула).
- Постановка задач — только `app.jobs.queue.enqueue` внутри транзакции доменной операции;
  обработчики регистрируются в `jobs/handlers/__init__.py::HANDLERS`, периодические задачи — в
  `jobs/scheduler.py::SCHEDULE`. Исполнитель выбирает только задачи типов из `HANDLERS`:
  задачи неизвестных типов ждут исполнителя, который их знает (поэтапный выпуск).
- Долгоживущие циклы (исполнитель, планировщик) не умирают от ошибок базы: `RECOVERABLE` →
  журнал, `pool.expire_connections()`, пауза, продолжение; ошибки программы — наружу.
- Состояние в процессе не хранится (§4.20 постановки): сессии и счётчики — в Redis.
