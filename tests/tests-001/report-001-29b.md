## Что задача принесла

- Постановка публикации (`CompositionService.enqueue_publish_user`, `enqueue_publish_node`,
  `remove_user(conn, user_id)`): задача очереди `critical` в транзакции вызывающего, ключ
  `{publish_user|publish_node}:{id}:{xid}` по `pg_current_xact_id()`; вне транзакции —
  `RuntimeError` до обращения к базе. Две постановки в одной транзакции — одна задача.
- `SubscriptionService`: шесть переходов ставят `composition.publish_user` в своей транзакции;
  прямых вызовов исполнителя после коммита не осталось; `expire` ставит задачу только при
  изменении.
- Удалённый пользователь (`users.status = 'deleted'`): условие в `_PAIR` — группу ни с одной
  нодой не разделяет, строки только `removed`, credentials удаляются; `blocked` не затрагивается.
- Исполнитель `composition.publish_node` (`publish_node(node_id, after)` на пуле,
  `publish_node_on` на подключении обработчика):
  - кандидаты порции — пользователи тарифов, чьи группы пересекаются с группами ноды, и
    пользователи со строкой не `removed` на ноде, по возрастанию `user_id`; читаются в короткой
    транзакции под блокировкой строки ноды;
  - на каждого пользователя — advisory-блокировка пользователя, своя транзакция с блокировкой
    строки ноды и записью пары (`_publish_pair`), снятие блокировки после коммита;
  - порция — до `PUBLISH_NODE_BATCH` = 200 пользователей; остаток — продолжение с `"after"` и
    ключом `publish_node:{node_id}:after:{user_id}` в конец очереди `critical`; пробуждение
    `PUBLISH node:{id}` — одно на порцию, после её последнего коммита;
  - нода удалена — порция останавливается без продолжения, `publish_user` эту ноду пропускает;
  - чужой ключ процесса (WI-38): строки без доступа пишутся, `active` пропускаются, продолжение
    ставится, нода будится, затем `CipherMismatch`.
- Обработчик `composition.publish_node`: нагрузка `{"node_id", "after"?}`, негодная —
  `NonRetryableError`.
- `PlanService._set_composition`: задачи `composition.publish_node` нодам групп симметрической
  разности прежнего и нового составов; строки прежних и новых групп блокируются `FOR UPDATE` по
  `id` до замены; связи с группами пишутся по возрастанию `id`; новый тариф публикацию не
  ставит.
- `GroupService.delete_access`: строка группы блокируется `FOR UPDATE` до чтения её нод и
  тарифов; группа, входившая хоть в один тариф, ставит `composition.publish_node` каждой своей
  ноде в транзакции удаления.
- `NodeService.create`: связи с группами пишутся по возрастанию `access_group_id`.
- Изоляция тестов: задачи публикации ставятся под типами `test-composition.*`
  (`tests/conftest.py`), живые исполнители стенда их не выбирают; `run_publications` исполняет их
  так же, как исполнитель очереди, и удаляет после теста.

### Решения

- Решения исполнителя (сигнатуры, постановка, симметрическая разность, изоляция тестов) — тело
  задачи, «Решения исполнителя (2026-11-05)». «Решить здесь» (сериализация с `publish_user`)
  разобрано до кода: первый путь, блокировка по одному пользователю.
- Решение заказчика 2026-11-05 (раунд 1, L3): состав ноды порциями по 200 с продолжением в конце
  `critical`. Замер стенда — 2,6 мс на пользователя, порция — около 0,52 с. Отклонённые варианты и
  остаток (раунд 2, R2-L3) записаны в «Примечаниях» задачи.
- Решения заказчика 2026-11-05 после раунда 3 (предел раундов исчерпан): находки раунда 3
  исправить без четвёртого роаста — посадки, `make check`, коммит; порция остаётся 200 при
  исправленном остатке: отзыв по квоте проходит очередь дважды и при смене групп тарифа на K нод
  больше чем с 200 пользователями ждёт около 2 × K × 0,52 с — при K = 10 (О-3) около 17,4 с вместе
  с цепочкой отзыва, в пределах максимума Н-13 до K = 50.
- Общий сценарий `publish_node` с числами (450 пользователей, порции по 200: отказ, повтор,
  падение исполнителя, конкурирующая публикация пользователя, чужой ключ, удалённая нода) —
  «Примечания» задачи.

## Тесты

`tests/e2e/test_composition_queue.py` (36, живая база стенда):

- TC-E2E-01 — переход ставит публикацию в своей транзакции; откат — задачи нет; после исполнения
  дельта несёт строку пользователя;
- каждый из шести переходов коммитит задачу вместе с собой: `xmin` задачи = `xmin` записанной
  переходом строки, хвост ключа `% 2**32` = этот `xmin`;
- одна транзакция — одна публикация на пользователя; две постановки ноды в одной транзакции —
  одна задача с ключом `publish_node:{node_id}:{xid}`;
- TC-E2E-02 — смена групп тарифа публикует ноды групп; неизменный состав и новый тариф — нет;
- TC-E2E-04 — удаление группы тарифа публикует её ноды; группа вне тарифов — нет;
- публикации нод коммитятся с операцией и ставятся на её подключении (смена групп тарифа,
  удаление группы);
- TC-E2E-03 — удалённый пользователь получает только `removed`; заблокированный сохраняет строку
  и credentials;
- `publish_node`: блокировка пользователя до блокировки ноды; одна блокировка пользователя за
  раз до коммита пары; кандидаты читаются после незакоммиченной записи пары; пробуждение после
  последнего коммита порции, каждая порция будит ноду;
- TC-E2E-05 — порции 2, 2, 1; публикация пользователя проходит между первой и второй порцией;
  ключи продолжений; полная последняя порция цепочку заканчивает; боевая порция — 200 (201
  пользователь → 200 строк и продолжение после 200-го);
- чужой ключ процесса: отзывы ноды пишутся, продолжение ставится и пишет следующую порцию;
- удалённая нода останавливает порцию, `publish_user` её пропускает;
- блокировки групп: удаление группы ждёт вставку связи с тарифом; смена групп тарифа ждёт ввод
  ноды в уходящую и во входящую группу; два изменения тарифов с общими группами не блокируют
  друг друга, изменение тарифа и создание тарифа или ноды — тоже; создание тарифа и создание ноды
  пишут связи по возрастанию `id`, повтор группы в запросе — одна связь. Группы этих тестов — с
  явными `id`, у которых порядок множества Python и порядок кучи обратны порядку `id`;
- постановка `publish_node` при смене групп тарифа и удалении группы видна в транзакции операции
  и не видна другой сессии до коммита.

`tests/unit/domain/test_composition.py`: постановка вне транзакции (×3), отказ исполнителям на
подключении в транзакции. `tests/unit/jobs/test_handlers.py`: боевые имена типов, нагрузки
`composition.publish_node` (негодные — `NonRetryableError`, `after` разбирается).
