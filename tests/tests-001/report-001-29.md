## Что задача принесла

- `next_users_seq(conn, node_id)` — номер изменения через `UPDATE nodes … RETURNING` в транзакции
  вызывающего; блокировка строки ноды упорядочивает коммиты по ноде.
- Исполнитель `composition.publish_user` (`CompositionService.publish_user` на пуле,
  `publish_user_on` на подключении обработчика; подключение в транзакции — `RuntimeError`):
  - публикации одного пользователя идут по очереди — сессионная advisory-блокировка
    (`PUBLISH_LOCK_CLASS` = 2901, ключ — `hashtext(user_id)`), взятая до выбора кандидатов;
  - ноды-кандидаты — пересечение групп доступа тарифа текущего периода с группами нод плюс ноды
    со строкой пользователя не в `removed`, порядок по `node_id`;
  - на каждую ноду своя транзакция: блокировка строки ноды `FOR NO KEY UPDATE` (режим `UPDATE
    nodes` и приёма отчёта), состояние пары под ней, номер — только когда строка пишется;
    общая группа — строка в состоянии подписки и credentials при отсутствии; группы нет —
    `removed` без адресов, запись credentials удаляется; размер гранта не трогается (001.36);
  - сбой посередине пробрасывается (задача повторяется целиком); пробуждения `PUBLISH
    node:{id}` номером строки — после коммита всех нод, первый отказ Redis прекращает остальные.
- Выдача (`state_for`): курсор ноды, её `resync_required` и строки — в одном снимке базы; дельта
  — строки с номером больше курсора ноды, снапшот — все, кроме `removed`, урезанный вентилем
  «снапшот» — дельтой от нуля (присланный курсор игнорируется); вентиль из `STREAM_GATE`; курсор
  по выборке до фильтра; урезанный ответ взводит `nodes.resync_required`; взведённый признак —
  повод ответить только там, где вентиль отдаёт состав целиком; credentials расшифровываются
  только у строк `active` ноды запроса.
- Обработчик `composition.publish_user`: полезная нагрузка `{"user_id"}`, негодная —
  `NonRetryableError`.
- Фиксированные строки заглушки ушли из боевого модуля в тесты: раскладка фикстур контракта
  (`tests/_agent.py`); герметичные прогоны — `RecordedComposition`, а живая служба на той же
  раскладке строками базы отвечает записанными фикстурами.

## Отклонения от описания задачи

- Снапшот (`full=1`) читает строки базы здесь, а не в 001.75b: иначе полный ответ нёс бы
  фиксированных пользователей заглушки поверх настоящей дельты. 001.75b остаются поколение,
  контрольная сумма состава и 409; её цель и строка изменений поправлены.
- `NOTIFY` после записи строки не вводится: подписчика нет, удержание ждёт канал Redis (§5.2);
  строка Н-13 в `interfaces.md` поправлена.
- Публикации одного пользователя сериализованы advisory-блокировкой (в описании не было; раунд 1,
  H-1).
- Фиксированные строки и credentials заглушки ушли из `app/domain/composition.py` в тесты;
  удалён модульный тест производных credentials заглушки — уникальность ключей на пару проверяет
  TC-E2E-07 на ключах, которые создаёт исполнитель.
- Тест гранта в `tests/e2e/test_reports.py` больше не сверяет грант строки состава с константой
  заглушки: публикация грант не пишет (владелец — 001.36).
