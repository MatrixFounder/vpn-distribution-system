## Закрытие задачи по решению заказчика (после роаста раунда 8)

Заказчик закрыл задачу как заглушку после эскалации раунда 8: без девятого роаста, с
дешёвыми исправлениями и передачей проектных вопросов владельцам. Семь решений, вынесенных на
эскалацию, взяты в рекомендованных вариантах по указанию «закрой задачу» — это выбор
исполнителя под этим указанием, и он записан здесь явно:

1. **Бюджет свободного текста (вариант А).** `app/body_shape.py`: строка с шаблоном, чей алфавит
   доказан разбором выражения (`re._parser`: только классы без отрицания, литералы, повторы,
   якоря с обоих концов; `.`, `[^…]`, `\S`, незакреплённый шаблон — «не доказано»), ничего не
   прибавляет; строка без шаблона с `max_length` прибавляет его к обоим пределам
   (`CommandResultIn.error` → 2 001/2 001); строка без того и другого и целое без `le` —
   `ValueError` при объявлении. `EnrollIn.csr_pem` получил алфавит PEM. Стенд (проба 25): текст
   ошибки с запятыми и скобками — 204; 2 100 ключей — 422 `too_wide`; 2 000 ключей ×200 —
   `urt` p50 3 / **p95 4** / max 57 мс — самая дорогая остальная операция теперь результат
   команды: `H4_OTHER_OPERATION_MS` = 4 (равенство с замером ассертом), окно гейта 116 ≤ 150,
   доля 64 ≤ 250. Предел серии цифр: у модели без строковых полей число длиннее `bigint`
   (19 знаков) — `too_wide` до разбора (`translate` + поиск подстроки, 0,5 мс на самой широкой
   части); стенд: 230 чисел по 4 300 цифр в 1 009 003 Б — 422 за p95 6 мс (×51; до закрытия
   такое тело стоило бы вдвое дороже законной части — 44 против 22 мс на рабочей машине).
2. **Ассерт суммы классов снят**, а не переписан: при потолке одновременности 2 цикл на насыщении
   занят отчётами целиком — это назначение потолка, задержку держит оконная модель; ёмкость на
   насыщении 1/p95 = 20 частей/с при спросе §5.7 около одной в секунду — числа в README,
   ARCHITECTURE §8.1 и 001.73 (16,2 части/с широкой частью, 20,3 компактной, 27 при 100 Мбит/с
   Н-17). Посадка R46 снята, I27b перенацелена на долю цикла.
3. **tmpfs не разделён** — передано 001.66/001.75 (потолок снапшота — их число); четыре
   документа больше не утверждают, что исчерпание не задевает Node API.
4. **411 — при отсутствии длины у любого метода, кроме GET и HEAD** (`~*^(?!get:|head:)[^:]+::$`);
   три текста сведены в один (§5.2, `state.py`, README). Стенд: DELETE, OPTIONS, POST без длины
   по HTTP/2 на отчёте и DELETE на enrollment — 411; DELETE с длиной — 405; GET состояния 200.
5. **Три случая удержания** (первая часть нового интервала — строка с `held`; удержанное
   продолжение — `held` на открытой строке; удержание по потолку открытых — строки нет) и
   **списанная доля удержанной части входит в `accepted_*`** — README, §5.2, data-model §4.2.5,
   001.34, передача 001.77.
6. **Потолок возраста — 48 часов** (`REPORT_MAX_INTERVAL_AGE`, два буфера Н-8, не меньше срока
   после последней части — оба ассертом), закрытие по возрасту — 001.37.
7. **Девятого роаста нет** — по указанию заказчика; закрывающая проверка — стражи, посадки, стенд,
   развёртка, аудит, шлюз ссылок (ниже).
